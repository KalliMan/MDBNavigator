# 1.4b UI polish: form controls

## 1. Goal

One look for text boxes, selects, checkboxes, buttons and notices, used by the connect dialog, the account page and the sign-in pages. Today the workspace and the sign-in pages each have their own set, with different heights, corners and focus marks. The connect dialog also gets a tighter layout, and the account page gets the workspace's top bar.

Roadmap step 1.4b. Changes these docs: `docs/specs/authentication.md` ("Pages", "Top bar", "Account page"), `mdb-navigator-ui/README.md` ("Source layout"), `docs/ROADMAP.md`.

UI only: no server file changes, no new packages.

**Before starting:** step 1.4a is committed (`git log` shows "UI polish: visible defects (roadmap 1.4a)" in the last commits) and `git status --short` shows nothing but this plan. Otherwise stop and ask.

## 2. Decisions

### Agreed with the owner on 2026-11-14

The UI polish is three steps: 1.4a visible defects (done), 1.4b one shared style for form controls (this plan), 1.4c surfaces and identity. For 1.4b the owner agreed to the outline: one style across the connect dialog, the account page and the sign-in pages; the account page gets the top bar; the colons after labels go.

### Decided by the planner (looks only, reversible; reported to the owner)

1. **Two sizes of one style.** `md`, 28 px high, inside the workspace: dialogs and the account page. `lg`, 36 px, on the sign-in pages, which stand alone and are the first thing a visitor sees. Everything else is the same in both: 3 px corners, the `line` border, the accent border plus a soft ring on focus for fields, an accent outline on keyboard focus for buttons and checkboxes, 50 % opacity when disabled, `fg-faint` placeholders.
2. **Connect dialog: labels stay left of the fields,** as in DBeaver, DataGrip and SSMS, without colons, in a column as wide as the longest label. Rows are 12 px apart (were 32 px). The dialog becomes about 200 px shorter and 80 px narrower.
3. **Host and Port share a row** (`Host [________] Port [5432]`), as database tools do. Port is a plain text box that takes digits only: a number box shows spinner arrows, which mean nothing for a port.
4. **The checkboxes sit in the field column,** under Color.
5. **The saved list fills the dialog's height,** from the title bar to the bottom edge, on the `surface` tone, and scrolls inside. Today its right border stops above the Color row.
6. **The connect error is a notice box** (the red-tinted box of the sign-in pages), not bare red text.
7. **The delete confirmation's `Delete` is red** (a new `danger` button type). The first `Delete`, which only asks, stays neutral.
8. **Sign-in and account pages: labels stay above the fields.** The password rule moves from the label (`Password (at least 8 characters)`) to a hint under the field (`At least 8 characters`).
9. **Account page:** the top bar above it; `md` controls; fields 320 px wide, buttons as wide as their text (were full-width fields and buttons in a 576 px card). `Unlink` and `Link` become buttons. `Delete my account…` becomes a neutral button; the confirming `Delete my account` is red.
10. **The app name in the top bar is a link to the workspace** (`/`), so the account page has the usual way back. "Back to the workspace" stays as well.
11. **Selects stay native** (`<select>`) with our own chevron: one option today, and a native list works with the keyboard and on phones. The toolbar's `Dropdown` is a menu for a different job.
12. **Checkboxes are drawn by us** (a 16 px box with 3 px corners and a check mark), over a real `<input type="checkbox">`, so they look the same in every browser and both themes.
13. **Cards (account sections, the sign-in card) get 6 px corners** (were 8 px), closer to the 3 px controls and the 4 px dialog.
14. **Not touched:** toolbar controls (the query bar's Run and menus, the result toolbar's filter box, Table | CSV switch and Export), text links ("Forgot password?", "Send the link again", "Retry"), the CAPTCHA widgets, colors and surface tones (1.4c).

### What we found in the code

- Two families. `ui/common/Input`, `Select`, `Button`: label on the left in a `1fr 2fr` grid, 32 px fields, 28 px buttons, 3 px corners; the `<label>` is not tied to its field (no `htmlFor`), so clicking it does nothing. `features/auth/AuthControls`: label above, about 38 px fields with 4 px corners, a full-width submit button, a different focus mark.
- Raw `<button>`s with their own classes: `AccountPage` (Unlink, Delete my account…, Delete my account, Cancel), `Root.tsx` (Try again). `ExternalSignInButtons` styles `<a>` as buttons.
- `ModalWindow` puts `pt-5` above its content; `CellViewer` takes it back with `-mt-5`.
- `Button` has a dead `to` prop and a commented-out import.
- `ConnectionColorPicker` renders its own label and grid row.
- The Port box is `type="number"` and stores `+val`: clearing it shows `0`.
- Body text is 14 px, so `text-sm` on these pages changes nothing.

## 4. Patterns to copy

| New thing | Mirror |
|---|---|
| A control component in `ui/common` | `ui/common/CloseButton.tsx` (one default export, a `Props` interface, theme tokens) |
| A label tied to its field with `useId`, `aria-invalid`, `aria-describedby` | today's `AuthField` in `features/auth/AuthControls.tsx` |
| An icon inside a control | `LuSearch` in `ui/dropdown/Dropdown.tsx` (`react-icons/lu`, `aria-hidden="true"`) |
| Class strings shared by several components | none yet: a `.ts` file next to the components (a component file may only export components, the lint rule `react-refresh/only-export-components`) |

Theme tokens only (`border-line`, `text-fg-muted`, `bg-danger-solid`), no palette classes, no `dark:` variants. Class names are written out in full (Tailwind finds them by reading the source, so never build a name from pieces such as `` `h-${n}` ``). Lint has zero warnings; no `as` casts. Keep every existing comment that explains why, moving it with its code.

### 5.2 `controlStyles.ts` (new)

```ts
import { ButtonType } from './ButtonType.enum';

// One look for every form control, in two sizes: 'md' (28 px) inside the workspace (dialogs, the account page),
// 'lg' (36 px) on the sign-in pages, which stand alone and are the first thing a visitor sees.
export type ControlSize = 'md' | 'lg';

const fieldBase = 'block w-full min-w-0 rounded-[3px] border bg-canvas text-fg outline-none placeholder:text-fg-faint '
  + 'focus:border-accent focus:ring-2 focus:ring-accent/30 disabled:cursor-not-allowed disabled:opacity-50';
const fieldSizes: Record<ControlSize, string> = { md: 'h-7 px-2', lg: 'h-9 px-3' };

// Text boxes and selects. A field always fills its container; the container sets the width.
export function fieldClass(size: ControlSize, invalid: boolean): string {
  return `${fieldBase} ${fieldSizes[size]} ${invalid ? 'border-danger' : 'border-line'}`;
}

const buttonBase = 'inline-flex flex-none items-center justify-center gap-1.5 rounded-[3px] font-medium whitespace-nowrap '
  + 'transition-colors cursor-pointer disabled:cursor-not-allowed disabled:opacity-50 '
  + 'focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent';
const buttonSizes: Record<ControlSize, string> = { md: 'h-7 px-3', lg: 'h-9 px-4' };
const buttonTypes: Record<ButtonType, string> = {
  primary: 'bg-accent text-on-accent hover:bg-accent-hover disabled:hover:bg-accent',
  secondary: 'border border-line bg-canvas text-fg hover:bg-hover disabled:hover:bg-canvas',
  danger: 'bg-danger-solid text-on-accent hover:opacity-90 disabled:hover:opacity-50',
};

// Also for a link that must look like a button (a provider's sign-in link leaves the page, so it is an <a>).
export function buttonClass(type: ButtonType, size: ControlSize = 'md', fullWidth = false): string {
  return `${buttonBase} ${buttonSizes[size]} ${buttonTypes[type]}${fullWidth ? ' w-full' : ''}`;
}
```

### 5.4 `TextInput.tsx` (new): the bare text box

```tsx
interface Props {
  id: string;
  type: 'text' | 'email' | 'password';
  value: string;
  onChange: (value: string) => void;
  size?: ControlSize;            // default 'md'
  invalid?: boolean;
  // The id of the paragraph that explains the field (its error or hint).
  describedBy?: string;
  placeholder?: string;
  maxLength?: number;
  autoComplete?: string;         // default 'on', as the old Input had
  autoFocus?: boolean;
  inputMode?: 'numeric';
}
```

Renders one `<input>` with `className={fieldClass(size, !!invalid)}`, `aria-invalid={invalid ? true : undefined}`, `aria-describedby={describedBy}`, `onChange={e => onChange(e.target.value)}`.

### 5.5 `FormField.tsx` (new): label, control, message

```tsx
interface Props {
  label: string;
  // The control's id: a click on the label focuses it. Without one (a group of buttons) the label is plain text.
  htmlFor?: string;
  // 'side': the label left of the control, for dialogs. 'stacked': the label above it, for pages.
  layout: 'side' | 'stacked';
  size?: ControlSize;            // default 'md'; in 'side' the label is as high as the control
  error?: string;
  // Shown under the control while there is no error.
  hint?: string;
  // The id of the error or hint paragraph; the control points at it with aria-describedby.
  messageId?: string;
  // 'stacked' only: on the label's line, right-aligned (e.g. a "Forgot password?" link).
  labelAside?: React.ReactNode;
}
```

- The message: `error ? <p id={messageId} className="text-sm text-danger">{error}</p> : hint ? <p id={messageId} className="text-xs text-fg-muted">{hint}</p> : null`.
- The label element: `<label htmlFor={htmlFor}>` when `htmlFor` is set, else `<span>`.
- `'side'` returns a fragment with **two grid cells**, so every row's label lands in the same column:

  ```tsx
  <>
    <LabelElement className={`flex items-center text-fg ${size === 'lg' ? 'h-9' : 'h-7'}`}>{label}</LabelElement>
    <div className="grid min-w-0 gap-1">{children}{message}</div>
  </>
  ```

  Comment: the parent must be a two-column grid (`grid-cols-[max-content_minmax(0,1fr)]`).
- `'stacked'`:

  ```tsx
  <div className="grid gap-1">
    <div className="flex items-baseline justify-between gap-3">
      <LabelElement className="font-medium text-fg">{label}</LabelElement>
      {labelAside}
    </div>
    {children}
    {message}
  </div>
  ```

(`LabelElement` stands for the `<label>` or `<span>` above; write it as a small conditional, not as a dynamic tag variable if that needs a cast.)

### 5.8 `Checkbox.tsx` (new)

```tsx
interface Props {
  checked: boolean;
  disabled?: boolean;
  onChange: (checked: boolean) => void;
}

// A real checkbox (keyboard, forms and screen readers get what they expect) with the browser's drawing switched
// off, so the box looks the same in every browser and both themes. children: the label's text.
export default function Checkbox({ checked, disabled, onChange, children }: React.PropsWithChildren<Props>) {
  return (
    <label className={`flex w-fit items-center gap-2 ${disabled ? 'cursor-not-allowed opacity-50' : 'cursor-pointer'}`}>
      <span className="relative flex size-4 flex-none">
        <input
          type="checkbox"
          checked={checked}
          disabled={disabled}
          onChange={e => onChange(e.target.checked)}
          className="peer size-4 cursor-[inherit] appearance-none rounded-[3px] border border-line bg-canvas checked:border-accent checked:bg-accent focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent"
        />
        <LuCheck size={12} strokeWidth={3} aria-hidden="true"
          className="pointer-events-none absolute inset-0 m-auto hidden text-on-accent peer-checked:block" />
      </span>
      {children}
    </label>
  );
}
```

## 6. Edge cases & don'ts

- **Enter in any field of the connect dialog must still connect.** `Connect` stays the form's only submit button (no `onClick`); every other `Button` in the form has an `onClick`.
- **On the account page each form has exactly one `Button` without `onClick`** (Change password; Delete my account). `Unlink`, `Delete my account…` and `Cancel` have handlers.
- **Don't change form logic:** `savedConnectionForm.ts`, `authValidation.ts`, `authErrors.ts`, the `update`/`select`/`handleSubmit` functions and the saved-password rules stay as they are. The only behavior change is the Port box (digits only, empty shows empty).
- **Don't put a width class on a field.** `fieldClass` always has `w-full`; wrap the field in a sized `<div>` instead (two width classes on one element don't override each other reliably).
- **Don't build class names from pieces,** and don't add palette classes or `dark:`.
- **Don't restyle toolbar controls, text links, the tree, the grid or the tabs,** and don't change colors or tokens in `index.css` (1.4c).
- **Don't swap the native `<select>` for `Dropdown`.**
- **`TopBar` on the account page is the same component,** not a copy. The hidden workspace keeps its own.
- **Password managers:** keep each field's `autoComplete` value as it is today (`TextInput` defaults to `'on'`, as `Input` did).
- **Placeholders stay** as 1.4a set them, except Port (`5432`).
- **Don't touch the CAPTCHA widgets.**
- **Never use ports 3000–3002,** don't start a second Vite dev server, don't run `npm install`.
- **Never commit.**
