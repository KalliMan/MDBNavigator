# 0.4b Compose setup

## 1. Goal

`docker compose up` starts the app and a PostgreSQL with a sample database, so someone who cloned the repository has something to look at within a couple of minutes: sign in, connect to the bundled database, browse it, and run a query that returns a million rows to see streaming and cancel.

Roadmap step **0.4b** ([ROADMAP.md](../ROADMAP.md), "0.4 Docker"). It builds on the image of 0.4a. The public demo (read-only role, guest access, HTTPS) is 0.5 and not part of this.

Docs it changes: `README.md` (the "Docker" section gets a "With Compose" part; its last sentence goes), `NOTICE` (Pagila's licence), `docs/ROADMAP.md` (plan link), the owner's local `CLAUDE.md` (a Compose bullet).

## 2. Decisions

- **Sample data: Pagila**, confirmed by the owner on 2026-11-15, plus **one table of a million rows** made for this purpose.
- **Pagila is downloaded when the sample database image is built**, from a pinned release of its repository, and each file's SHA-256 is checked. Vendoring it would put about 3 MB of SQL into this repository; an unpinned download could change under us.
- **The sample database is its own small image** (`docker/sample-db/Dockerfile`, based on `postgres:17-alpine`): Pagila's schema and data, then one script of ours. PostgreSQL runs the scripts once, when its data volume is empty.
- **The big table is `demo.measurements`:** one million rows from `generate_series`, with a number, a timestamp, a decimal and a text column, so the grid shows several value kinds. It is generated, not downloaded.
- **Local try-out, not a deployment:**
  - The app's port is published on **127.0.0.1 only**.
  - Sign-up is **closed** and one admin is seeded. With closed sign-up the connection guard is off by default, so the admin can also reach their own databases (`host.docker.internal`).
  - The admin's email and password have **defaults that the README states**, and can be set in a `.env` file. Defaults are acceptable only because the port is not reachable from other machines; the README says to change them before exposing anything.
- **PostgreSQL's port is not published.** The app reaches it by its service name, `sample-db`. Publishing 5432 would collide with databases people already run.
- **The sample database's user owns it** (`sample` / `sample`, database `pagila`): people can create and change things. `docker compose down -v` resets it. The read-only role is for the public demo (0.5a).
- **Remembered passwords are off unless a key is given** (`MDBNAV_PASSWORD_KEY` in `.env`), as everywhere else.
- **Compose project name `mdbnavigator`**, set in the file, so volumes and containers get predictable names.

## 5. Contracts

### `docker-compose.yml`

```yaml
# A local try-out: the app and a PostgreSQL with sample data.
#   docker compose up --build
# Then open http://localhost:8080 and sign in (see README, "With Compose").
# Not a deployment: no HTTPS, a default password, and the port is open to this machine only.
name: mdbnavigator

services:
  app:
    build: .
    image: mdbnavigator:local
    ports:
      # This machine only. Put a reverse proxy with TLS in front before opening it to others.
      - "127.0.0.1:${MDBNAV_PORT:-8080}:8080"
    environment:
      # One admin, created at the first start. Nobody else can create an account.
      Auth__SignUp: Closed
      Auth__Admin__Email: ${MDBNAV_ADMIN_EMAIL:-admin@example.com}
      Auth__Admin__Password: ${MDBNAV_ADMIN_PASSWORD:-change-this-password}
      # Optional: lets saved connections remember passwords (openssl rand -base64 32).
      SavedConnections__PasswordKey: ${MDBNAV_PASSWORD_KEY:-}
    volumes:
      - app-data:/app/data
    depends_on:
      sample-db:
        condition: service_healthy
    restart: unless-stopped

  sample-db:
    build: docker/sample-db
    image: mdbnavigator-sample-db:local
    environment:
      POSTGRES_USER: sample
      POSTGRES_PASSWORD: sample
      POSTGRES_DB: pagila
    volumes:
      - sample-db-data:/var/lib/postgresql/data
    healthcheck:
      # Healthy only once the sample data is loaded: the init scripts run before PostgreSQL accepts TCP connections.
      test: ["CMD-SHELL", "pg_isready -h 127.0.0.1 -U sample -d pagila"]
      interval: 5s
      timeout: 3s
      retries: 30
    restart: unless-stopped

volumes:
  app-data:
  sample-db-data:
```

### `docker/sample-db/Dockerfile`

```dockerfile
# PostgreSQL with sample data for trying MDBNavigator: Pagila (a DVD rental shop: about 20 tables, views,
# functions) and one table of a million rows to show streaming and cancel.
FROM postgres:17-alpine

# Pagila, from a fixed release, each file checked against its SHA-256: the data can't change under us.
# https://github.com/devrimgunduz/pagila (PostgreSQL licence)
ARG PAGILA_REF=<tag>
ARG PAGILA_SCHEMA_SHA256=<sha256 of pagila-schema.sql at that tag>
ARG PAGILA_DATA_SHA256=<sha256 of pagila-data.sql at that tag>

RUN set -eux; \
    cd /docker-entrypoint-initdb.d; \
    wget -q -O 10-pagila-schema.sql "https://raw.githubusercontent.com/devrimgunduz/pagila/${PAGILA_REF}/pagila-schema.sql"; \
    wget -q -O 20-pagila-data.sql "https://raw.githubusercontent.com/devrimgunduz/pagila/${PAGILA_REF}/pagila-data.sql"; \
    echo "${PAGILA_SCHEMA_SHA256}  10-pagila-schema.sql" | sha256sum -c -; \
    echo "${PAGILA_DATA_SHA256}  20-pagila-data.sql" | sha256sum -c -; \
    chmod 644 *.sql

# Ours, after Pagila.
COPY 90-measurements.sql /docker-entrypoint-initdb.d/
```

Filling in the three values is part of this step:

- `PAGILA_REF`: the newest release tag of `devrimgunduz/pagila` (find it with `gh api repos/devrimgunduz/pagila/tags` or `git ls-remote --tags https://github.com/devrimgunduz/pagila`). A tag, not a branch.
- The two checksums: download both files at that tag once and compute `sha256sum`.
- If the repository has no tags, pin a full commit SHA of its default branch instead and say so in the comment. If the files are named differently at that tag, use the plain-SQL schema file and the `COPY`-format data file (not the `INSERT` variant) and report what you used.

### `docker/sample-db/90-measurements.sql`

```sql
-- One large table, so there is a query that streams for a while and can be cancelled:
--   select * from demo.measurements;
-- A million rows with a number, a timestamp, a decimal and a text, generated rather than downloaded.
create schema demo;

create table demo.measurements as
select g                                                              as id,
       timestamptz '2026-01-01 00:00:00+00' + g * interval '30 seconds' as taken_at,
       1 + (g % 50)                                                    as sensor,
       round((20 + 10 * sin(g / 1000.0) + (g % 7) * 0.25)::numeric, 3) as value,
       'reading ' || g                                                 as note
from generate_series(1, 1000000) as g;

alter table demo.measurements add primary key (id);
create index measurements_sensor_taken_at on demo.measurements (sensor, taken_at);

comment on table demo.measurements is 'A million generated rows, to show streaming and cancel.';

analyze demo.measurements;
```

No random values: every build of the image gives the same rows.

## 6. Edge cases & don'ts

- **Test runs must not collide with anything of the owner's.** Use `docker compose -p mdbnav-0-4b` and `MDBNAV_PORT=18080`, and finish with `docker compose -p mdbnav-0-4b down -v`. Don't run plain `docker compose up` in the repository (that would create the real `mdbnavigator` project), and don't touch containers, volumes or images you did not create (`PostgreSQLDB`, `what2eat-postgres`, the old `mdbnavigator-*` ones).
- **Don't create a `.env` file in the repository.** Pass test values through the environment of the command.
- **Don't publish PostgreSQL's port**, and don't connect anything to the owner's PostgreSQL on 5432.
- **No secret in any file**: the defaults in the Compose file are the documented try-out values only.
- **The download is pinned and checked.** No `latest`, no branch name, no unchecked file. If a checksum fails, the build must fail.
- **`90-measurements.sql` must run after Pagila** (the file names' numbers decide the order) and must not depend on Pagila's objects.
- **The app must not start before the sample data is loaded**, or the first connect would fail: that is what `depends_on: condition: service_healthy` and the TCP health check are for. Verify it (section 8), don't assume it.
- **Don't change application code.** If something in the app has to change for Compose to work, stop and report.
- **LF line endings** for the Compose file, the Dockerfile, the SQL file and `.env.example`.
- **Don't push or publish images.**
