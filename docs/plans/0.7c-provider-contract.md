# 0.7c Provider contract

## 1. Goal

A small project, `MDBNavigator.Providers.Abstractions`, that holds everything a database provider must offer and nothing else. The PostgreSQL provider references only that project, moves to `src/Providers/MDBNavigator.Providers.PostgreSQL`, and its one 486-line class becomes four focused ones. The fat `IDatabaseProvider` interface (20 members) becomes an open connection with three parts: read the schema, generate scripts, run queries.

Roadmap step **0.7c** ([ROADMAP.md](../ROADMAP.md), "0.7 Modular structure"). No behavior change: the same endpoints, status codes, JSON and hub messages. The smoke tests of 0.7b must pass without any change to them.

Docs it changes: `README.md` ("Supported servers" line, "Repository layout"), `mdb-navigator-ui/README.md` (two paths), four UI comments, `docs/ROADMAP.md` (one name), the owner's local `CLAUDE.md` (one path).

## 2. Decisions

- **Names say what the things are.** Today `IDbServerFactory` is the provider and `IDatabaseProvider` is an open connection. After this step:
  - `IDatabaseProvider`: one per server type; it opens clients. (Was `IDbServerFactory`.)
  - `IDatabaseClient`: one open connection to one database; disposing closes it. (Was `IDatabaseProvider`.)
  - `ISchemaReader`, `IScriptGenerator`, `IQueryRunner`: the three parts of a client.
- **A client has three parts, not three base interfaces.** `client.Schema.GetTables()`, `client.Scripts.GetDropTableScript()`, `client.Queries.StreamQuery()`. This is what lets the PostgreSQL class be split into a reader, a generator and a runner that share one connection.
- **The procedure and view definitions belong to scripts**, not to the schema reader: they return SQL text for the editor, and their routes are under `databaseCommand`.
- **`GetCreateFunctionProcedureScript` is renamed `GetCreateFunctionScript`.** The old name was a slip.
- **The provider's own "not found" error:** `DatabaseObjectNotFoundException` in the contract project, thrown where the provider throws `ObjectNotFoundException` today, with the same messages, and mapped to 404 by the same middleware arm. The provider must not reference the core, and saved connections keep their `ObjectNotFoundException`.
- **`ConnectionSettings`, `ServerType`, `ServerTypes`, the schema models, the stream items and `DbTypeCategory` move into the contract project.** They are what crosses the boundary between the app and a provider. `MDBNavigator.Domain` keeps `SavedConnection` and the exceptions until 0.7e and 0.7d move them.
- **`IDatabaseErrorDescriber` moves unchanged.** One describer for all providers is a limitation that matters only with a second provider; it is not solved here.
- **`IDatabaseProviderFactory` (the app's own dispatcher that applies the connection guard) keeps its name and place** in `MDBNavigator.Application`; only its return type changes. It moves and is renamed in 0.7e.
- **New PostgreSQL classes use the prefix `Postgres`**, as `PostgresScriptSplitter` and `PostgresErrorDescriber` already do. `PostgreSQLServiceRegistration.AddPostgreSQLProvider` keeps its name: `Program.cs` calls it.
- **Service lifetimes stay as they are** (`IDatabaseProvider` scoped, the describer singleton).
- **The unit test project follows its subject:** `tests/MDBNavigator.Providers.PostgreSQL.Tests`.

### The interfaces (namespace `MDBNavigator.Providers.Abstractions`)

```csharp
// One per database server type (PostgreSQL; later MS SQL Server). The app picks the provider by ServerType.
public interface IDatabaseProvider
{
    ServerType ServerType { get; }

    // Connects to one of the addresses (tried in order), never to settings.ServerName: the addresses are the ones
    // IConnectionGuard checked, and resolving the name again could give a different one.
    Task<IDatabaseClient> ConnectAsync(ConnectionSettings settings, IReadOnlyList<IPAddress> addresses, string? databaseName = null, CancellationToken ct = default);
}

// One open connection to one database. Disposing it closes the connection.
public interface IDatabaseClient : IAsyncDisposable
{
    string DataSource { get; }
    ISchemaReader Schema { get; }
    IScriptGenerator Scripts { get; }
    IQueryRunner Queries { get; }
}

// What the tree shows. Async members take the request's CancellationToken, so an abandoned request stops its database call.
public interface ISchemaReader
{
    Task<IEnumerable<DbDatabase>> GetDatabases(CancellationToken ct = default);
    Task<IEnumerable<DbTable>> GetTables(CancellationToken ct = default);
    Task<TableDefinition> GetTableDefinition(string schema, string table, CancellationToken ct = default);
    Task<IEnumerable<DbProcedure>> GetStoredProcedures(CancellationToken ct = default);
    Task<IEnumerable<DbProcedure>> GetFunctions(CancellationToken ct = default);
    Task<IEnumerable<DbView>> GetViews(CancellationToken ct = default);
}

// SQL text for the editor: templates, and the definitions of existing objects.
// Throws DatabaseObjectNotFoundException when the named object does not exist.
public interface IScriptGenerator
{
    string GetTopNTableRecordsScript(string schema, string table, int? recordsNumber);
    string GetCreateNewTableScript(string schema);
    Task<string> GetCreateTableScript(string schema, string table, CancellationToken ct = default);
    string GetDropTableScript(string schema, string table);
    Task<string> GetInsertTableScript(string schema, string table, CancellationToken ct = default);

    string GetCreateStoredProcedureScript(string schema);
    string GetCreateFunctionScript(string schema);
    Task<string> GetProcedureDefinition(string schema, string name, CancellationToken ct = default);
    Task<string> GetDropProcedureScript(string schema, string name, CancellationToken ct = default);

    Task<string> GetViewDefinition(string schema, string name, CancellationToken ct = default);
    string GetCreateViewScript(string schema);
    string GetDropViewScript(string schema, string name);
}

public interface IQueryRunner
{
    // (the comment block that is on IDatabaseProvider.StreamQuery today moves here unchanged)
    IAsyncEnumerable<QueryStreamItem> StreamQuery(
        string script,
        int batchSize,
        int? commandTimeoutSeconds = null,
        int? maxRowsPerResultSet = null,
        QueryStreamStats? stats = null,
        CancellationToken ct = default);
}

// A table, view or routine the request names does not exist in the database. The API answers 404.
public class DatabaseObjectNotFoundException : Exception
{
    public DatabaseObjectNotFoundException(string message) : base(message) { }
}
```

The five classes. Method bodies, SQL text and comments move as they are; nothing in them is rewritten.

```csharp
public class PostgresProvider : IDatabaseProvider
{
    public ServerType ServerType => ServerType.PostgreSQL;
    public async Task<IDatabaseClient> ConnectAsync(ConnectionSettings settings, IReadOnlyList<IPAddress> addresses, string? databaseName = null, CancellationToken ct = default)
        => await PostgresClient.OpenAsync(settings, addresses, databaseName, ct);
}

// Owns the connection. The three parts share it.
public sealed class PostgresClient : IDatabaseClient
{
    private readonly NpgsqlConnection _connection;

    private PostgresClient(NpgsqlConnection connection);    // creates the three parts over the connection

    public string DataSource => _connection.DataSource;
    public ISchemaReader Schema { get; }
    public IScriptGenerator Scripts { get; }
    public IQueryRunner Queries { get; }

    // Today's PostgreSQLServer.ConnectAsync: the same connection string, the same loop over the addresses with
    // the same two catch blocks and comments. It returns the client once a connection is open.
    internal static Task<PostgresClient> OpenAsync(ConnectionSettings settings, IReadOnlyList<IPAddress> addresses, string? databaseName, CancellationToken ct);

    public ValueTask DisposeAsync();    // disposes the connection
}

// Each takes the connection in its constructor and keeps it in a readonly field named _connection,
// so the moved method bodies stay as they are.
internal sealed class PostgresSchemaReader : ISchemaReader
internal sealed class PostgresScriptGenerator : IScriptGenerator
internal sealed class PostgresQueryRunner : IQueryRunner

internal static class PostgresCommands
{
    // Dapper command carrying the request's cancellation token.
    internal static CommandDefinition Command(string sql, object? parameters = null, CancellationToken ct = default);
}
```

| Member | Goes to |
|---|---|
| `_connection`, `DataSource`, `DisposeAsync`, `ConnectAsync`, `DisconnectAsync` | `PostgresClient` |
| `GetDatabases`, `GetTables`, `GetTableDefinition`, `GetStoredProcedures`, `GetFunctions`, `GetViews`, `GetProceduresInternal` | `PostgresSchemaReader` |
| `GetCreateStoredProcedureScript`, `GetCreateFunctionProcedureScript` (renamed `GetCreateFunctionScript`), `GetProcedureDefinition`, `GetDropProcedureScript`, `GetViewDefinition`, `GetCreateViewScript`, `GetDropViewScript`, `GetTopNTableRecordsScript`, `GetCreateNewTableScript`, `GetCreateTableScript`, `GetDropTableScript`, `GetInsertTableScript`, `GetTableScript`, `QuoteIdentifier`, `QualifiedName`, the constants `RoutineKinds` and `QualifiedRelationSql` | `PostgresScriptGenerator` |

## 6. Edge cases & don'ts

- **Do the two renames in this order**, or the names collide: first `IDatabaseProvider` to `IDatabaseClient` everywhere, then `IDbServerFactory` to `IDatabaseProvider`.
- **Don't rewrite SQL, messages or comments while moving code.** A diff of a moved method body must show only what this plan names (the class it is in, `Command` to `PostgresCommands.Command`, the exception type, `ProcedureType`).
- **Don't change any route, DTO, JSON property or hub message.** `src/MDBNavigator.API/Controllers/*` change only in their `using` lines.
- **Don't touch the smoke tests** (`tests/MDBNavigator.API.Tests`). If one fails, the refactoring is wrong, not the test. If you are sure a test is wrong, stop and ask.
- **The provider project must not reference `Application`, `Domain` or `Infrastructure`**, not even indirectly. Check its `obj/project.assets.json` or simply its `.csproj`: one project reference.
- **`Providers.Abstractions` references nothing**, no packages either.
- **Keep `JsonCellValue`, `PostgresScriptSplitter` and `PostgresStatementRules` exactly as they are** apart from the namespace: the 90 unit tests cover them.
- **Dispose behavior stays:** a handler's `await using` closes the connection; a failed connect leaves no open connection.
- **`PostgresClient` is not registered in the container.** Only `PostgresProvider` creates it.
- **The moved folders hold git-ignored `bin/` and `obj/`.** Delete them in the moved projects before `git mv` (as in 0.7a), and delete `obj/` of the projects whose references changed if the build complains about stale paths.
- **Visual Studio must not have the solution open** while folders move. If `git mv` fails with "Permission denied", stop and report.
- **Don't change the older plans in `docs/plans/`.** They keep the paths that were true when they were written.
- **`MediatR` stays** in this step; it goes in 0.7d.

## 7. Steps
