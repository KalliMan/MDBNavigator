# 1.3c Result grid: sort and filter

## 1. Goal

A result can be sorted by a column and narrowed with a filter box that searches every column. Both work in the browser on the rows already loaded, through a list of row indexes, so rows are never copied. Matches are marked in the cells, and rows keep their numbers from the original result.

Roadmap step 1.3c (`docs/ROADMAP.md`), built on the branch `1.3-result-grid` after 1.3b. UI only. Changes these docs: root `README.md` ("Features"), `mdb-navigator-ui/README.md` (the last paragraph of "How a query runs in the UI"). Mock: https://claude.ai/artifact/8YCZfS9K3puEqj7Gigjg5e (boards "1.3c Sort and filter" and "1.3c While rows are arriving").

**Before starting:** 1.3b must be in the working tree: `mdb-navigator-ui/src/ui/dataGrid/CellViewer.tsx` exists and `npm test` passes. Otherwise stop and ask. Read section 5 of `docs/plans/1.3a-select-copy.md` and `docs/plans/1.3b-resize-cell-viewer.md` first; this step builds on those contracts.

## 2. Decisions

Agreed with the owner on 2026-11-13:

1. **One filter box over all columns** (case-insensitive "contains"). Per-column filters may come later.
2. **Sort and filter are off until the result is complete.** Sorting a list that is still growing makes rows jump. Selecting, copying and resizing work while rows arrive.
3. **Sort and filter cover the loaded rows only.** The server stops a run at its row limit (100,000 by default), and the status bar says so. Beyond that the database does the work: the user writes `ORDER BY` or `WHERE`.
4. **Matches are marked** in the cells.
5. **Row numbers stay those of the original result** after sorting or filtering.
6. **The tools strip above the grid is always there**, also for a single result.

Decided by the planner (small, reversible):

- **A header click still selects the column (1.3a). Sorting has its own button in the header**, shown when the pointer is over the header and whenever the column is sorted. It cycles ascending → descending → off. This is how DBeaver and pgAdmin do it, and it keeps "copy a whole column" one click away. (The mock's note said "click a header to sort"; this replaces it.)
- **NULLs sort last** in both directions.
- **How values compare** depends on the column's `category` only: `Number` numerically (exact for `bigint` and `numeric`, which arrive as text), `Boolean` false before true, `Text` with the browser's collation (`Intl.Collator`), everything else by its text code units (ISO dates and times sort correctly that way).
- **The filter is applied 200 ms after the last keystroke.**
- **Sorting or filtering clears the selection**, because the rows under it move.

### What we found in the code

- A result set's `isComplete` turns true only when its last batch arrives. A cancelled or failed run never sends one, so "the result is complete" must also be true when the run is over: `resultSet.isComplete || !isExecuting`.
- `DataGrid` (1.3a) already reaches rows only through `rowCount` and `getRow`. A view changes those two and nothing else.
- Export and the CSV view (1.3d) need the same filtered and sorted rows, so the view lives in the feature component, not inside the grid. The grid receives it.

## 5. Contracts

### 5.1 `rowView.ts`

```ts
export type SortDirection = 'asc' | 'desc';

export interface SortState {
  column: number;
  direction: SortDirection;
}

// The next step of a header's sort button: off → ascending → descending → off. Another column starts ascending.
export function nextSort(current: SortState | null, column: number): SortState | null

// One lower-cased line of text per row, built once per result so that every keystroke in the filter box only
// searches strings. Cells are joined with a character that can't be typed, so a match never spans two cells.
export function buildSearchText(rows: CellValue[][]): string[]

// Order of two non-null values of a column; negative when a comes first.
export function compareValues(a: CellValue, b: CellValue, category: DbTypeCategory): number

// The rows to display, as indexes into rows, or null for "all rows in their original order".
// filter is matched case-insensitively against every cell; an empty or blank filter matches everything.
export function buildView(
  rows: CellValue[][],
  categories: DbTypeCategory[],
  searchText: string[] | null,
  filter: string,
  sort: SortState | null,
): Int32Array | null

export interface TextPart { text: string; match: boolean; }

// Splits text at every case-insensitive occurrence of needle, for marking matches. An empty needle gives one part.
export function matchParts(text: string, needle: string): TextPart[]
```

Rules:

- `buildSearchText`: for each row, `row.map(v => cellToText(v).toLowerCase()).join('\u0000')`. NULL contributes the empty string, so NULL never matches.
- `buildView`:
  - `needle = filter.trim().toLowerCase()`. With no needle and no sort, return `null`.
  - With a needle, keep the indexes whose `searchText[i]` includes the needle. (`searchText` is required then; when it is `null`, build it with `buildSearchText(rows)`.)
  - With a sort, order the kept indexes by the sort column: NULL (`null` or `undefined`) after every value in both directions; otherwise `compareValues`, negated for `desc`; equal values keep their original order (compare the indexes).
  - Return an `Int32Array`.
- `compareValues`:
  - `Number`: compare `Number(value)` of each (a number stays as it is; a string is parsed). Order: `-Infinity`, finite numbers, `Infinity`, `NaN` last (PostgreSQL's order). When the two parsed numbers are equal and both values are strings, break the tie with an exact decimal comparison of the strings (sign, then the integer part by length and digits, then the fraction digit by digit), so `'9007199254740993'` sorts after `'9007199254740992'`. A string that is not a number compares as `NaN`.
  - `Boolean`: `false` before `true`.
  - `Text`: a module-level `Intl.Collator(undefined)`'s `compare` on `cellToText` of each.
  - Every other category: `cellToText` of each, compared with `<` and `>`.
- `matchParts`: search `text.toLowerCase()` for `needle.toLowerCase()` repeatedly; parts cover the whole text in order; no empty parts.

`rowView.test.ts`: `nextSort` through the whole cycle and when switching columns; `buildView` returning `null` with nothing to do; a filter that matches in different columns and in different letter case; a filter that would only match across two cells (no match); a NULL cell with the filter `null` (no match); sort ascending and descending on numbers; `bigint` strings beyond 2^53; `numeric` strings such as `'10.5'`, `'9.75'`, `'-3'`, `'10.50'`; `'NaN'` and `'Infinity'` strings; NULLs last in both directions; a stable order for equal values; text sorting where an upper-case word must not come before all lower-case ones (`'apple'`, `'Banana'`, `'cherry'`); ISO timestamps; filter and sort together; `matchParts` with no match, one match, two matches, a match at each end, and different case.

### 5.3 `DataGrid.tsx`

New props, after `rows`:

```ts
// The rows to display, as indexes into rows; null shows all rows in their original order.
view: Int32Array | null;
sort: SortState | null;
onSortChange: (sort: SortState | null) => void;
// False while rows are still arriving: the sort buttons are hidden.
canSort: boolean;
// Text to mark in the cells (the filter). Empty: nothing is marked.
highlight: string;
```

- **`rowCount` and `getRow`** become `view ? view.length : rows.length` and `(index: number) => rows[view ? view[index] : index]`. Everything else already goes through them.
- **Row numbers:** `(view ? view[item.index] : item.index) + 1`. `rowNumberWidth` is computed from `rows.length` (the largest number that can appear), not from `rowCount`.
- **The cell viewer's `rowNumber`** becomes that original number too.
- **The selection is cleared when `view` changes.** In the render body, with a state `shownView` holding the view the selection belongs to: `if (shownView !== view) { setShownView(view); setSelection(null); setViewer(null); setMenu(null); }`. The parent clears its own copy of the selection size in the same handlers that change the filter or the sort (5.5), so `onSelectionChange` is not called here.
- **Sort button** in each header cell, only when `canSort`. The header cell becomes `group flex items-center gap-1` with the name in a `<span className="min-w-0 flex-1 truncate">` and then:

```tsx
<button
  type="button"
  aria-label={`Sort by ${column.name}`}
  title={sorted ? (sorted === 'asc' ? 'Sorted ascending. Click for descending.' : 'Sorted descending. Click to clear.') : 'Sort ascending'}
  onPointerDown={e => e.stopPropagation()}
  onClick={() => onSortChange(nextSort(sort, c))}
  className={`flex size-5 flex-none items-center justify-center rounded-[3px] cursor-pointer hover:bg-hover focus-visible:opacity-100 ${
    sorted ? 'text-accent-strong' : 'text-fg-muted opacity-0 group-hover:opacity-100'
  }`}
>
  {sorted === 'asc' ? <LuArrowUp size={13} aria-hidden="true" />
    : sorted === 'desc' ? <LuArrowDown size={13} aria-hidden="true" />
    : <LuArrowUpDown size={13} aria-hidden="true" />}
</button>
```

  with `sorted = sort?.column === c ? sort.direction : null`. `onPointerDown` stops the header's column selection. The header cell gets `aria-sort` (`'ascending'`, `'descending'` or `'none'`). The resize handle (1.3b) stays on top of the button's right edge.
- **Header width:** the sort button and its gap take 24px of the header cell, so `headerWidths` and `fitColumnWidth` (`columnWidths.ts`) add `HEADER_SORT_SPACE = 24` to the measured name. Without it every column name was cut ("pati…", "first_…"). The room is kept while the button is hidden, so widths don't jump when a run finishes. (Added after the owner's first look, 2026-11-13.)
- **Marked matches:** when `highlight.trim()` is not empty and the cell is not NULL, the cell's content is `matchParts(cell.text, highlight.trim())` rendered as text and `<mark className="rounded-[2px] bg-match text-inherit">` elements. Otherwise the plain text, as before. (The displayed text is cut at 1,000 characters, so a match further in is not marked; the row still passes the filter.)

### 5.4 `ResultToolbar.tsx`

### 5.5 `DatabaseCommandSingleResultView.tsx`

New prop `isExecuting: boolean` (from `DatabaseCommandResultView`, which has it).

```ts
// Rows stop arriving when the result set's last batch came, or when the run is over (a cancelled or failed run
// never sends a last batch). Only then can the rows be sorted and filtered.
const canArrange = resultSet.isComplete || !isExecuting;
```

State: `filterText` (what the box shows), `filter` (applied), `sort: SortState | null`. A ref holds the debounce timer.

- `handleFilterChange(text)`: `setFilterText(text)`; clear the timer; when `text` is empty apply at once, else start a 200 ms timer; applying means `setFilter(text)` and `onSelectionChange(resultSet.id, null)`. An unmount cleanup clears the timer.
- `handleSortChange(next)`: `setSort(next)` and `onSelectionChange(resultSet.id, null)`.
- `const categories = useMemo(() => resultSet.fields.map(f => f.category), [resultSet.fields]);`
- `const searchText = useMemo(() => (canArrange && filter.trim() ? buildSearchText(resultSet.rows) : null), [canArrange, filter, resultSet.rows]);`
- `const view = useMemo(() => (canArrange ? buildView(resultSet.rows, categories, searchText, filter, sort) : null), [canArrange, resultSet.rows, categories, searchText, filter, sort]);`
- Layout: `<div className="flex h-full flex-col">`, the `ResultToolbar` (`rowCount={resultSet.rows.length}`, `shownCount={view ? view.length : resultSet.rows.length}`, `enabled={canArrange}`, `filter={filterText}`, `filterApplied={filter === filterText}`, `onFilterChange={handleFilterChange}`), then `<div className="min-h-0 flex-1">` with the `DataGrid` (`view`, `sort`, `onSortChange={handleSortChange}`, `canSort={canArrange}`, `highlight={canArrange ? filter : ''}`).
- When the filter leaves no rows, the grid shows its header and no rows, and the strip says "0 of N rows". Nothing else is needed.

`searchText` is rebuilt only when the rows change, which they no longer do once `canArrange` is true, so typing in the filter never rebuilds it. `buildSearchText` runs only when a filter is first used.

`DatabaseCommandResultView.tsx` passes `isExecuting` to each `DatabaseCommandSingleResultView`. The stacked layout stays in this step (each result has its own strip); 1.3d replaces it with tabs.

## 6. Edge cases & don'ts

- **Don't sort or filter while rows arrive.** `view` is `null` and `highlight` is empty until `canArrange`.
- **Don't copy or reorder `rows`.** The view is an index array; `rows` belongs to the reducer.
- **Don't compute the view inside `DataGrid`.** The feature component owns it (1.3d's export needs it).
- **Don't use `localeCompare` on every comparison** (slow on 100,000 rows); use one `Intl.Collator` instance.
- **Don't parse `bigint` or `numeric` text with `Number` alone**: equal doubles are tie-broken on the text.
- **Don't read `dataTypeName` or the value's JavaScript type to pick a comparison.** Only `category`.
- **Don't debounce with an effect.** The timer is started in the change handler.
- **A text typed while rows were arriving** can't exist: the box is disabled until `canArrange`.
- **A new run** remounts the component (its key holds the execution id), so filter and sort reset.
- **Sorting keeps column widths**; they belong to the columns, not the rows.
- **A selection, the cell viewer and the context menu** are cleared when the view changes.
- **Copy with a view** copies the displayed rows in displayed order (it already goes through `getRow`).
- **`fitColumnWidth` (1.3b)** already takes `getRow` and `rowCount`, so it measures the displayed rows.
- **Lint has zero warnings.**
- **Never commit.**
