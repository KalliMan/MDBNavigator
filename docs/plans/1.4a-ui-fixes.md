# 1.4a UI polish: visible defects

## 1. Goal

Fix the small things that make screenshots look unfinished: column types cut off in the tree, tab arrows that are always there, an editor that takes two thirds of the height, numbers aligned like text, timestamps with an ISO `T`, and the connect dialog's wording and button order.

Roadmap step 1.4a (new; this step adds 1.4a, 1.4b and 1.4c to `docs/ROADMAP.md`). Changes these docs: root `README.md` ("Streaming query results": the batch example and the cell value table; "Development"), `docs/ROADMAP.md`.

**Before starting:** step 1.3e is committed: `git status --short` shows nothing but this plan (and possibly `docs/plans/1.4b-…`, `1.4c-…`), `MDBNavigator.Infrastructure.PostgreSQL.Tests/` exists and `dotnet test MDBNavigator.Infrastructure.PostgreSQL.Tests -o <scratch>/tests` passes. Otherwise stop and ask.

## 2. Decisions

### Agreed with the owner on 2026-11-14

The UI polish is three steps: 1.4a visible defects (this plan), 1.4b one shared style for form controls, 1.4c surfaces and identity. The defect list comes from the owner's screenshots of the workspace, the connect dialog and the account page, in both themes.

### Decided by the planner (small and reversible; reported to the owner)

1. **Tree, columns:** `first_name varchar(50) not null`. The name in the normal weight and color, the type short, lower-case and muted, `not null` faint. A nullable column says nothing (most columns are nullable, so the marker that carries information is `not null`). The full text (`first_name: character varying(50), not null`) is the row's tooltip.
2. **Tree, short type names:** only PostgreSQL's long standard names are shortened, to the aliases PostgreSQL itself accepts: `character varying` → `varchar`, `character` → `char`, `timestamp without time zone` → `timestamp`, `timestamp with time zone` → `timestamptz`, `time without time zone` → `time`, `time with time zone` → `timetz`. Everything else is only lower-cased.
3. **Tree, indexes and constraints:** names in the normal weight; the tag (`(PK, Unique)`) and the constraint type (`primary key`, lower-case) muted. The per-type colors (orange, blue, grey) go: three colors and bold on every row were the "too many emphases".
4. **Tree, typo:** the folder is "Programmability" (was "Programability"). Only the label; the `NodeType` value stays.
5. **Query tabs:** the two scroll arrows show only while the tabs don't fit.
6. **Editor height:** 40 % of the tab's height until the splitter is dragged (was a fixed 580 px, which left ten result rows on a laptop screen). Not remembered between tabs or visits; that can come later with the sidebar width.
7. **Numbers are right-aligned** in the grid, header included; in a numeric column the sort button moves to the left of the name, so the name ends where the numbers end.
8. **Dates and times are written as PostgreSQL writes them,** on the server: `2026-01-22 15:19:01.785309` in place of `2026-01-22T15:19:01.785309`. Doing it in the grid only would break the filter: it searches the value's text, so typing what the grid shows (`2026-01-22 15`) would find nothing. On the server, the grid, the filter, copy, CSV and JSON export all show the same text. See 5.9 for each type. **This changes exported values** (JSON export had ISO 8601 strings); the owner should know.
9. **Right padding:** the query bar and the result toolbar get 12 px on the right, like the status bar (they had 8 px). The "text touches the window edge" in the owner's screenshots was mostly the screen capture cutting a few pixels; this only makes the three bars agree.
10. **Connect dialog wording:** title "Connect to a server" (reconnect: "Reconnect to the server"), sentence case; "Host" and "User" for "Server Name" and "User Name"; placeholders that name the field, not "Type … here..."; "Save changes to this connection". The colons after labels stay until 1.4b restyles the form.
11. **Connect dialog buttons:** `Delete` and `Forget password` on the left, `Cancel` and `Connect` on the right, `Connect` last.
12. **`Button` sets its HTML type:** a button with an `onClick` is `type="button"`, one without is `type="submit"`. Today every `Button` is a submit button and the handlers call `preventDefault()`. That only works while Connect is the first button in the form: pressing Enter in a field clicks the form's first submit button, which after the reorder would be `Delete`.

### What we found in the code

- Column types come from `information_schema.columns.data_type` (`character varying`, `timestamp without time zone`, `USER-DEFINED`, `ARRAY`), upper-cased in `createTableColumnNode`.
- `TreeViewNode` renders `nodeTextElement ?? nodeText ?? nodeName`; `nodeText` is used for nothing else.
- `Tabs.tsx` always renders both arrow buttons.
- `HorisontalSidebar` (used only by `DatabaseCommandAndResult`) starts at 580 px and already limits itself with `max-height: calc(100% - 120px)`, so percentages resolve there.
- `JsonCellValue.From` passes `DateTime`, `DateTimeOffset` and `TimeOnly` through, and System.Text.Json writes them. Probed on 2026-11-14: `timestamp` → `2026-01-22T15:19:01.785309`; `timestamptz` → a UTC `DateTime`, `2026-01-22T13:19:01.785309Z`; `time` → `15:19:01.7853090` (seven digits); `time with time zone` → a `DateTimeOffset` on a made-up date, `0001-01-02T15:19:01.785309+02:00`; `date` → `1955-10-11`.
- The grid sorts `DateTime` columns by their text (`rowView.compareValues`), which stays correct: the new form is year-first with fixed-width fields too.
- The UI has no test for the tree's helpers; `formatCell`, `rowView` and others show the pattern.

## 5. Contracts

### 5.1 `columnTypeText.ts` (new, pure)

```ts
// A column's type as the tree shows it: lower-case, with PostgreSQL's long standard names shortened to the
// aliases PostgreSQL itself accepts. Names it doesn't know are only lower-cased.
export function shortTypeName(dataType: string, maxLength?: number): string;

// The same without shortening, for the tooltip.
export function fullTypeName(dataType: string, maxLength?: number): string;
```

- Both lower-case `dataType` and append `(maxLength)` when `maxLength` is a number above 0.
- `shortTypeName` maps, after lower-casing: `character varying` → `varchar`, `character` → `char`, `timestamp without time zone` → `timestamp`, `timestamp with time zone` → `timestamptz`, `time without time zone` → `time`, `time with time zone` → `timetz`.

`columnTypeText.test.ts`: each of the six mappings; `CHARACTER VARYING` with 50 → `varchar(50)`; `character` with 1 → `char(1)`; `INTEGER` → `integer`; `USER-DEFINED` → `user-defined`; `maxLength` `undefined` and `0` add nothing; `fullTypeName('character varying', 50)` → `character varying(50)`.

### 5.9 `JsonCellValue.cs`

`DateTime`, `DateTimeOffset` and `TimeOnly` leave the pass-through list and get their own arms, before it:

```csharp
// Dates and times are written the way PostgreSQL writes them, so the grid, the filter, copy and export all
// show what psql shows. Fraction digits are dropped when zero, as PostgreSQL does.
DateTime dt => dt.ToString("yyyy-MM-dd HH:mm:ss.FFFFFF", CultureInfo.InvariantCulture)
    // Npgsql reads "timestamp with time zone" as UTC, whatever the session's time zone is.
    + (dt.Kind == DateTimeKind.Utc ? "+00" : ""),
// Only "time with time zone" arrives as a DateTimeOffset, on a made-up date: the time and the offset are the value.
DateTimeOffset dto => dto.ToString("HH:mm:ss.FFFFFF", CultureInfo.InvariantCulture) + OffsetText(dto.Offset),
TimeOnly t => t.ToString("HH:mm:ss.FFFFFF", CultureInfo.InvariantCulture),
```

`private static string OffsetText(TimeSpan offset)`: sign, two-digit hours, and `:mm` only when the minutes are not zero: `+02`, `+00`, `-03:30`.

`DateOnly` stays in the pass-through list (`1955-10-11` already).

## 6. Edge cases & don'ts

- **Don't change `NodeType.Programability`** or any node id: the tree's expand state and lookups use them.
- **Don't shorten type names the map doesn't know.** `double precision`, `USER-DEFINED` and `ARRAY` are only lower-cased.
- **Don't set state in the body of the `Tabs` effect.** The observer's first report does the first measurement.
- **Don't remember the editor height** (no `localStorage`) in this step.
- **Don't format dates in the UI.** `formatCell` and `cellToText` stay as they are; the server's text is the value.
- **Don't touch `DateOnly`, intervals or infinity.** `interval` still arrives as .NET writes it (`1.02:03:04`), `infinity` as `9999-12-31 …`, and a BC date still fails in Npgsql. Those need the provider to read such columns as text, which is a step of its own.
- **Don't leave a `preventDefault()` on a `Button` click** in the connect dialog, and don't give `Connect` an `onClick`.
- **Don't restyle the dialog** (label colons, input sizes, native select and checkboxes): that is 1.4b.
- **Enter in any field of the connect dialog must still connect,** also with a saved connection selected (when `Delete` is in the row).
- **The delete confirmation** keeps its text; only the two buttons move to the right and swap.
- **Never use ports 3000–3002,** don't start a second Vite dev server, don't run `npm install`. Build the API with `-o` into a scratch folder.
- **The owner's PostgreSQL is read-only.**
- **Never commit.**
