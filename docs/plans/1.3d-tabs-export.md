# 1.3d Result grid: result tabs, Table or CSV, export

## 1. Goal

A run with several result sets shows one tab per result set, in place of the stacked grids. A switch shows the active result as a table or as CSV text, and an Export menu downloads it as a CSV or JSON file. All three show the same rows: the loaded ones, with the current sort and filter.

Roadmap step 1.3d (`docs/ROADMAP.md`), the last step of 1.3, built on the branch `1.3-result-grid` after 1.3c. UI only. Changes these docs: root `README.md` ("Features"), `mdb-navigator-ui/README.md` (the last paragraph of "How a query runs in the UI"). Mock: https://claude.ai/artifact/8YCZfS9K3puEqj7Gigjg5e (boards "1.3d Result tabs and export" and "1.3d Output as CSV").

**Before starting:** 1.3c must be in the working tree: `mdb-navigator-ui/src/features/databaseCommand/ResultToolbar.tsx` exists and `npm test` passes. Otherwise stop and ask. Read section 5 of the three earlier plans (`docs/plans/1.3a-…`, `1.3b-…`, `1.3c-…`) first; this step builds on those contracts.

## 2. Decisions

Agreed with the owner on 2026-11-13:

1. **One tab per result set**, in the tools strip. The strip is there for a single result too.
2. **A Table | CSV switch**, like "results to grid / results to text" in SQL Server Management Studio.
3. **Export downloads CSV or JSON, made in the browser from the loaded rows.** A full server-side export would be a separate, later feature.
4. **Export and the CSV view follow the table:** the rows in view, with the current sort and filter.
5. **Export is off while rows are arriving**, like sort and filter.

Decided by the planner (small, reversible):

- **The CSV view is a read-only Monaco editor** (already bundled): it handles 100,000 lines, and it gives selection, Ctrl+A, Ctrl+C and find without new code.
- **While rows are arriving, the CSV view shows a note** in place of the text (rebuilding megabytes of text several times a second would stall the page). The table view keeps streaming as before.
- **CSV rules** (RFC 4180, with PostgreSQL's convention for NULL): comma-separated, a header row, lines end with CRLF; a field is quoted when it contains a comma, a quote or a line break, with quotes doubled; NULL is an empty field and an empty string is `""`, so the two can be told apart. The downloaded file starts with a UTF-8 byte order mark, so Excel reads Cyrillic and other non-Latin text; the CSV view and the clipboard have none.
- **JSON rules:** an array with one object per row, keyed by column name. Values are exactly what the server sent, so `bigint` and `numeric` are strings (JavaScript and many JSON readers would round them). A `Json` column's value is embedded as JSON, not as a string. A repeated column name gets `_2`, `_3`.
- **File name:** `{database}_result{N}_{yyyyMMdd}_{HHmmss}.csv` (local time).
- **The Table | CSV choice belongs to the query tab** (all its results), and starts as Table for every new tab.
- **Counts are written with thousands separators** (`1,234 rows`) in the strip and the status bar.

### What we found in the code

- `DatabaseCommandSingleResultView` owns one result's filter, sort and view (1.3c). Every result keeps its own, so all results stay mounted and the inactive ones are hidden, the way query tabs already work in `ui/tabs/Tabs.tsx`.
- The grid is hidden, not unmounted, in CSV mode, so its column widths, selection and scroll position survive the switch.
- `ui/dropdown/Dropdown.tsx` already is a keyboard-accessible menu button with a footer. The Export menu uses it.
- Monaco's themes and bundled setup come from `features/databaseCommand/monacoSetup.ts`; `plaintext` is part of the editor core, so no language has to be added.

## 5. Contracts

### 5.1 `resultExport.ts`

```ts
export type ExportFormat = 'csv' | 'json';

export interface ExportColumn { name: string; category: DbTypeCategory; }

// rows and view as in the grid: view lists the rows to write, in order; null means all rows.
export function toCsv(columnNames: string[], rows: CellValue[][], view: Int32Array | null): string
export function toJson(columns: ExportColumn[], rows: CellValue[][], view: Int32Array | null): string

// One JSON key per column: a repeated name gets _2, _3, ... so no value is lost.
export function jsonKeys(columnNames: string[]): string[]

export function exportFileName(databaseName: string, resultNumber: number, at: Date, format: ExportFormat): string
```

`toCsv`:

- First line: the column names. Then one line per row. Lines are joined with `\r\n`; there is no line break after the last one.
- A field: `null`/`undefined` → nothing; otherwise `cellToText(value)`; the empty string becomes `""`; text containing `,`, `"`, `\r` or `\n` is wrapped in `"` with every `"` doubled; anything else is written as it is. Column names follow the same rule.

`toJson`:

- `[`, then one line per row (two spaces, then the object), joined with `,\n`, then `\n]`. No rows: `[]`.
- An object: `{"key": value, "key": value}` with keys from `jsonKeys` written with `JSON.stringify`.
- A value: `null`/`undefined` → `null`. In a `Json` column, a string that `JSON.parse` accepts (in a `try`) is written as that text itself, trimmed and unparsed, so no digit changes; a string it rejects is written with `JSON.stringify`. Every other value is written with `JSON.stringify(value)`.

`jsonKeys`: the first use of a name keeps it; a later one becomes `name_2`, `name_3`, …, skipping any key already taken.

`exportFileName`: `` `${safe}_result${resultNumber}_${yyyyMMdd}_${HHmmss}.${format}` `` in local time, zero-padded. `safe` is `databaseName` with every run of characters outside `A-Z a-z 0-9 _ -` replaced by `_`; when that leaves nothing, `query`.

`resultExport.test.ts`: `toCsv` with plain values; NULL versus the empty string; a comma, a quote and a line break in a field; a header name with a comma; a view that reorders and drops rows; no rows (the header line only). `toJson` with numbers, booleans, NULL, a `bigint` string (stays a string); a `Json` column (embedded as JSON, a large number inside keeps every digit; the output parses with `JSON.parse`); a `Json` column holding invalid JSON (a string); a `Text` column holding JSON-looking text (a string); an array value; a view; no rows. `jsonKeys(['id', 'id', 'name', 'id', 'id_2'])` gives five different keys. `exportFileName('my db/1', 2, new Date(2026, 10, 13, 9, 5, 7), 'csv')` is `my_db_1_result2_20261113_090507.csv`, and an empty database name gives `query_result…`.

### 5.2 `utils/download.ts`

```ts
// Saves text as a file through a temporary link, entirely in the browser.
export function downloadText(fileName: string, text: string, mimeType: string): void {
  const url = URL.createObjectURL(new Blob([text], { type: mimeType }));
  const link = document.createElement('a');
  link.href = url;
  link.download = fileName;
  document.body.appendChild(link);
  link.click();
  link.remove();
  // Revoked a little later: some browsers start the download only after this function has returned.
  setTimeout(() => URL.revokeObjectURL(url), 1000);
}
```

## 6. Edge cases & don'ts

- **Don't build CSV text for a hidden result or while rows arrive.** `csvText` is `null` in both cases.
- **Don't unmount the grid in CSV mode.** It is hidden, so widths, selection and scroll survive.
- **Don't unmount inactive results.** Their filter, sort and widths live in their components.
- **Don't add a dependency** (no CSV or file-saver library).
- **Don't `JSON.parse` a `Json` value into the export** and write it again; embed the text, so large numbers keep their digits.
- **Don't put the byte order mark into the CSV view** or into `toCsv`; only the download adds it.
- **Don't ask the server for anything.** Export uses the rows already in the browser.
- **A truncated result** exports what was loaded; the status bar already says that the row limit was reached.
- **A result with columns and no rows** has a tab ("0 rows"), an empty grid, and exports a header line (CSV) or `[]` (JSON).
- **Statements without a result set** (`INSERT`, DDL) get no tab; when a run has no result set at all, the "records affected" line shows as before.
- **A new run** replaces the result sets: the active tab falls back to the first, and the Table | CSV choice stays.
- **Many result sets** (dozens): the tabs scroll horizontally inside the strip; the tools on the right stay in place.
- **The Export menu's cast** (`key as ExportFormat`) is the only `as` this step adds.
- **Lint has zero warnings.**
- **Never commit.**
