# 0.5b3 Start page and named invite codes

## 1. Goal

With the demo on, someone who opens the site without being signed in sees a public start page (what MDBNavigator is, screenshots, later a video, GitHub) instead of the bare sign-in form. The demo gets several invite codes, each with a name (LinkedIn, CV, Friends): one can be changed or switched off alone, and each visitor's record and the owner's "new visitor" email say which link they came by.

Roadmap 0.5b3. Changes README "Public demo setup" and "Configuration" (Demo table), `docs/api.md` (join), `docs/security.md` "Public demo" (Guests), `docs/specs/authentication.md` "Demo guests", `docs/ROADMAP.md` 0.5b3 row (plan link), `compose.demo.yaml`, `.env.example`, `.github/workflows/ci.yml`.

## 2. Decisions

Agreed with the owner on 2026-11-20:

- Named invite codes, all three uses: change one alone, see where each visitor came from, switch one channel off. To start with: LinkedIn, CV, Friends.
- A public start page for recruiters who won't sign up. The owner records a short video on 2026-11-21; until then the page shows screenshots, and the video goes into a ready slot (one constant).

My calls inside this plan:

- **The start page is `/` for anyone not signed in, when the demo is on.** Without the demo nothing changes (`/` still goes to `/login`). After an expired session (`sessionExpired`), `/` still goes to `/login`, so the "Your session has ended" notice isn't lost.
- **The links to share are `https://<address>/?code=<code>`**: the start page first, and its "Try the demo" button carries the code on to `/demo?code=<code>`. Without a code, the page shows no button but says the demo is by invitation. Anyone can see the page; only people with a link can join. `/demo?code=` links keep working, and the join page gets a "What is MDBNavigator?" link back to `/?code=`.
- **The code is not checked when the start page opens**, only when the form is sent (as today). Checking earlier would give anyone a way to test codes without a CAPTCHA.
- **`Demo:InviteCodes` replaces `Demo:InviteCode`.** A list of `{ Name, Code }`. An entry with an empty `Code` is switched off (its links stop), so a channel is closed by blanking one environment variable. At least one code must be set. The old `Demo:InviteCode` stops startup with a message naming the new setting, so an old configuration can't silently lose its code.
- **The visitor keeps the name of the link they first came by** (`demo_visitors.invite_name`); joining again through another link doesn't change it. Returning visitors' sign-in links carry none.
- **Screenshots are served by the app** (`public/start/*.png`): the Content Security Policy allows images only from the app itself (`img-src 'self' data:`), so the GitHub-hosted README images can't be used directly. The video will be a file in `public/start/` too (`default-src 'self'` covers it).
- **No new tests in the UI** (the page is markup); API tests cover the codes.

## 5. Contracts

### Settings

```csharp
// One invite link's secret, with a name that says where the link was shared (LinkedIn, CV, ...).
public class DemoInviteCode
{
    public const int NameMaxLength = 30;
    public string Name { get; set; } = string.Empty;
    // Empty: switched off, its links don't work.
    public string Code { get; set; } = string.Empty;
}

// In DemoOptions, replacing the InviteCode property:
public List<DemoInviteCode> InviteCodes { get; set; } = [];

// Replaced by InviteCodes; only read to stop startup with a clear message when an old configuration still sets it.
public string InviteCode { get; set; } = string.Empty;

// The code's entry, or null. Compares with every switched-on code in constant time and doesn't stop at a match,
// so the answer's timing gives away neither the code nor which entry matched.
public DemoInviteCode? FindInviteCode(string? given);
```

Validation (with `Enabled`), each added to `problems`:
- `InviteCode` not empty → "Demo:InviteCode is replaced by Demo:InviteCodes (a list of Name and Code)".
- No entry with a non-empty `Code` → "Demo:InviteCodes needs at least one code".
- An entry's `Name` empty, longer than 30, or with characters other than letters, digits, space, `-`, `_` → "Demo:InviteCodes names must be 1-30 letters, digits, spaces, - or _".
- Names not unique (ignoring case) → "Demo:InviteCodes names must be unique".
- A non-empty `Code` shorter than `InviteCodeMinLength` (16) → "Demo:InviteCodes codes must have at least 16 characters".
- Non-empty codes not unique → "Demo:InviteCodes codes must be unique".

Configuration shape (environment variables): `Demo__InviteCodes__0__Name`, `Demo__InviteCodes__0__Code`, `__1__`, ...

### Data (migration `AddDemoInviteNames`)

- `demo_sign_in_links.invite_name`: `string?`, max 30. Set by `join`; null for `sign-in-link`.
- `demo_visitors.invite_name`: `string?`, max 30. Set when the visitor is created, from the link; never changed afterwards. (Visitors from before this step: null.)

### `DemoAccess`

- `RequestJoinLinkAsync(string name, string email, string inviteName, CancellationToken ct)`; `RequestLinkAsync` gets `string? inviteName` and stores it on the link.
- `StartAsync`: the new visitor gets `InviteName = link.InviteName`. An existing visitor's `InviteName` is not touched.
- The owner email: `EmailTemplates.NewDemoVisitor(_options.OwnerEmail, visitor.Name, visitor.Email, visitor.InviteName)`.

## 6. Edge cases & don'ts

- Never log a code, a name or an email. The invite name may be logged ("New demo visitor (link: LinkedIn)") — it is the owner's own label, not personal data.
- `FindInviteCode` must not return early or skip switched-off entries in a way that changes timing; compare the given code with every entry (an empty entry never matches).
- Don't check the code on the start page or add an endpoint for it.
- Don't load images or video from other sites (CSP).
- Don't change `/` without the demo, and don't show the start page to someone whose session just expired.
- A code in the URL must be URL-encoded when put into links.
- No new project or project reference. No change to existing test classes other than `DemoTests` (new tests only) and `DemoAppFixture`.
- Don't commit. Don't touch the owner's user secrets or `.env`; the summary lists what the owner must change (Opus does the user-secrets move after verification).
