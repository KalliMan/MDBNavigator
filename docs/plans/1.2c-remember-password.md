# 1.2c Remember password

## 1. Goal

A saved connection can optionally remember its password. The password is encrypted on the server with AES-GCM and a key from `SavedConnections:PasswordKey`, and it never goes back to the browser. When the user connects from a saved entry with the password field left empty, the server decrypts the remembered password and uses it. Reconnecting does the same. The option shows up only when the key is set.

Roadmap step 1.2c (`docs/ROADMAP.md`). Builds on 1.2a and 1.2b, on the same branch (`1.2-saved-connections`, merged when 1.2a–1.2d are all done). Changes these README sections: the "Security status" note, "Features", "Configuration" (a new row plus a new subsection, "Remembered passwords"), and "API" (the `connect`, `reconnect` and `savedConnections` rows, plus a new row for forgetting a password). Decisions agreed with the owner on 2026-11-13.

**Before starting:** `git log --oneline -3` must show the 1.2b commit ("Saved connections: connect dialog (roadmap 1.2b)"), and `git status` must be clean apart from this plan. Otherwise stop and ask the owner.

## 2. Decisions

Agreed with the owner on 2026-11-13 (the 1.2a plan settled the first two; the rest were settled for this step):

- **AES-GCM with our own key, not ASP.NET Core Data Protection.** The Data Protection keys live in the same SQLite file as the passwords would, so anyone with the file could decrypt them. The key is 32 random bytes in base64, read from `SavedConnections:PasswordKey`: an environment variable (`SavedConnections__PasswordKey`) or user secrets, never `appsettings*.json`.
- **Off unless the key is set.** Without the key nothing is stored, the UI doesn't offer the option, and passwords stored earlier are ignored (they stay in the database, unreadable, and work again if the same key comes back).
- **The password never goes back to the browser.** The API returns only `hasPassword: true`. To use the remembered password, connect and reconnect send `savedConnectionId` with an empty `password`. The server then loads the entry (owner-checked), decrypts the password and connects. The decrypted password exists only in server memory, the same way a typed one does today.
- **The UI flag is only a hint; the server checks for itself.** `GET api/auth/settings` returns `rememberPasswords: true|false`, and the UI uses it to show or hide the checkbox. The server checks the key on every write: with no key, a request that asks to remember a password gets `400` "Remembering passwords is not turned on for this server." It doesn't matter how that request was made (dev tools, curl). A `savedConnectionId` the user doesn't own gets `404`, as everywhere else in 1.2a.
- **Changing the server type, server name, port or user name deletes the remembered password**, unless the same request brings a new one. The owner asked how other tools handle this. Desktop tools (DBeaver, DataGrip, pgAdmin) keep the password when you edit the host. Tools that file passwords under server and login (SSMS, Azure Data Studio, browser password managers) effectively don't carry it to a new server. A web app is the second case. With a stolen session or an XSS bug, someone could point a saved entry at their own server and press Connect, and our server would send them the password. Deleting the password on such an edit closes that gap. The same check runs on connect: the remembered password is used only when the request's server type, server name, port and user name match the saved entry. The database name may differ, because it's the same server and the same login.
- **Each encrypted password is bound to its row.** The AES-GCM associated data is the saved connection's id plus its owner id. An encrypted value copied into another row, or into another user's row, fails to decrypt.
- **Bad key, changed key:** a key that is set but isn't valid base64, or isn't exactly 32 bytes, stops startup with a clear message. A stored password written with another key, or one that fails to decrypt (changed or damaged), counts as "no password". The list shows `hasPassword: false`, connect asks for the password ("Password is required."), and saving with "Remember password" replaces it. No error page and no `500`.
- **Telling which key a password was written with, without decrypting it:** each stored value starts with a 4-byte key id, the first 4 bytes of SHA-256 of the key. The list compares key ids, so it never decrypts anything, and decrypting happens only on connect.
- **UI:** a "Remember password" checkbox under "Save this connection" / "Save changes". It only applies when that checkbox is ticked, because the password is saved with the entry, after a successful connect, as in 1.2b. A "Forget password" button next to Delete is shown when the selected entry has a remembered password. It works right away, without connecting.
- **Storage:** a nullable `protected_password` BLOB column on `saved_connections`, added by the migration `AddSavedConnectionPassword`.
- **Reconnect uses the remembered password too.** The connect result carries `savedConnectionId` when the connection was opened with a remembered password. The reconnect dialog then makes the password optional and sends that id when the field is left empty. **Accepted limit:** a connection opened with a *typed* password carries no id, so its reconnect dialog asks for the password even if "Remember password" was ticked during that connect. The next connect from the saved list uses the remembered one.
- **The key is the only switch.** It isn't tied to `ConnectionGuard` or to `Auth:SignUp`. The README warns that on a public instance it means the server holds strangers' database passwords.
- **No new dependencies.** `System.Security.Cryptography.AesGcm` comes with .NET.

## 5. Contracts

### 5.1 Application: the protector contract

`MDBNavigator.Application/Contracts/ISavedPasswordProtector.cs`:

```csharp
namespace MDBNavigator.Application.Contracts
{
    // Encrypts the passwords that saved connections remember (SavedConnections:PasswordKey). Each value is bound to
    // its row: the same bytes in another row, or under another owner, don't decrypt.
    public interface ISavedPasswordProtector
    {
        // False when SavedConnections:PasswordKey isn't set: passwords are then neither stored nor used.
        bool Enabled { get; }

        // Throws InvalidOperationException when not Enabled (callers check Enabled first).
        byte[] Protect(string password, Guid savedConnectionId, string ownerId);

        // True when the value was written with the current key, so Unprotect can be expected to work. Doesn't decrypt,
        // so listing saved connections never decrypts anything.
        bool IsCurrent(byte[] protectedPassword);

        // Null when not Enabled, written with another key, or changed or damaged (the tag doesn't match). Never throws
        // for a bad value.
        string? Unprotect(byte[] protectedPassword, Guid savedConnectionId, string ownerId);
    }
}
```

### 5.4 Application: `RememberedPassword.cs`

`MDBNavigator.Application/Features/SavedConnections/RememberedPassword.cs`:

```csharp
using FluentValidation;
using MDBNavigator.Application.Contracts;
using MDBNavigator.Domain.Entities;
using MDBNavigator.Domain.Enums;
using MDBNavigator.Domain.Exceptions;
using MDBNavigator.Domain.ValueObjects;

namespace MDBNavigator.Application.Features.SavedConnections
{
    // The rules for using and keeping a remembered password, shared by the saved-connection handlers and connect/reconnect.
    public static class RememberedPassword
    {
        public const string NotEnabledMessage = "Remembering passwords is not turned on for this server.";
        // The connect validator's wording, so the user sees one message whichever check caught it.
        public const string RequiredMessage = "Password is required.";

        // The remembered password belongs to one server and login. Used on connect (only then is it sent) and on update
        // (an edit to any of these forgets it). Otherwise a stolen session could point a saved entry at its own server
        // and have us send it the password. Host names ignore case, as DNS does. User names don't: PostgreSQL's are
        // case-sensitive. The database is not part of it: same server, same login.
        public static bool SameTarget(SavedConnection saved, ServerType serverType, string serverName, int port, string userName)
            => saved.ServerType == serverType
               && string.Equals(saved.ServerName, serverName.Trim(), StringComparison.OrdinalIgnoreCase)
               && saved.Port == port
               && string.Equals(saved.UserName, userName.Trim(), StringComparison.Ordinal);

        // The settings to connect with, and the saved connection whose remembered password they use (null: the request's
        // own password). A typed password always wins; the id is then not even looked up.
        // Throws ObjectNotFoundException (404) for an id the user doesn't own, and ValidationException (400, RequiredMessage)
        // when there is nothing usable: no key, no password, another key, a changed value, or another server or user.
        public static async Task<(ConnectionSettings Settings, Guid? UsedSavedConnectionId)> ResolveAsync(
            ISavedConnectionStore store, ISavedPasswordProtector passwords, string userId,
            ConnectionSettings settings, Guid? savedConnectionId, CancellationToken cancellationToken)
        {
            if (savedConnectionId is not { } id || !string.IsNullOrEmpty(settings.Password))
            {
                return (settings, null);
            }

            var saved = await store.FindAsync(userId, id, cancellationToken)
                ?? throw new ObjectNotFoundException("Saved connection not found.");

            var password = passwords.Enabled
                           && saved.ProtectedPassword is { } protectedPassword
                           && SameTarget(saved, settings.ServerType, settings.ServerName, settings.Port, settings.UserName)
                ? passwords.Unprotect(protectedPassword, saved.Id, saved.OwnerId)
                : null;
            if (password is null)
            {
                throw new ValidationException(RequiredMessage);
            }

            // The saved entry's own (trimmed) server and user name: they are what the password was remembered for.
            return (settings with { ServerName = saved.ServerName, UserName = saved.UserName, Password = password }, saved.Id);
        }
    }
}
```

`FindAsync` returns a tracked entity; nothing is saved here, so that is harmless.

**EF mapping:** `ProtectedPassword` needs no configuration line. The snake-case convention names the column `protected_password`, and `byte[]?` becomes a nullable BLOB. If the generated migration names it differently, stop and ask.

### 5.7 Infrastructure: options, key, protector

`MDBNavigator.Infrastructure.Accounts/SavedConnectionOptions.cs`:

```csharp
namespace MDBNavigator.Infrastructure.Accounts
{
    public class SavedConnectionOptions
    {
        public const string SectionName = "SavedConnections";

        // 32 random bytes in base64, e.g. from `openssl rand -base64 32`. A secret: user secrets or an environment
        // variable (SavedConnections__PasswordKey), never appsettings.json. Not set: passwords aren't remembered.
        public string? PasswordKey { get; set; }

        // Null when not set (empty counts as not set). Throws at startup for a key that can't be right, rather than
        // failing at the first saved password.
        public static byte[]? ParseKey(string? value)
        {
            if (string.IsNullOrWhiteSpace(value))
            {
                return null;
            }
            byte[] key;
            try
            {
                key = Convert.FromBase64String(value.Trim());
            }
            catch (FormatException)
            {
                throw new InvalidOperationException(KeyMessage);
            }
            return key.Length == 32 ? key : throw new InvalidOperationException(KeyMessage);
        }

        private const string KeyMessage =
            "SavedConnections:PasswordKey must be 32 random bytes in base64 (44 characters), for example from `openssl rand -base64 32`.";
    }
}
```

`MDBNavigator.Infrastructure.Accounts/Passwords/AesGcmSavedPasswordProtector.cs` (namespace `MDBNavigator.Infrastructure.Accounts.Passwords`):

```csharp
    // AES-GCM with a 256-bit key from SavedConnections:PasswordKey. Not Data Protection: its keys are stored in the same
    // SQLite file as these passwords, so the file alone would be enough to read them.
    //
    // Stored value: version (1 byte, 1) | key id (4) | nonce (12) | tag (16) | ciphertext (UTF-8 password).
    // The key id (first 4 bytes of SHA-256 of the key) tells a value written with another key apart without decrypting.
    // The nonce is random per value: a 96-bit random nonce is safe for far more passwords than one instance will ever store.
    // The associated data binds the value to its row (id and owner), so it can't be moved to another row or user.
    public sealed class AesGcmSavedPasswordProtector : ISavedPasswordProtector
    {
        private const byte FormatVersion = 1;
        private const int KeyIdSize = 4;
        private const int NonceSize = 12;
        private const int TagSize = 16;
        private const int HeaderSize = 1 + KeyIdSize + NonceSize + TagSize;

        private readonly byte[]? _key;
        private readonly byte[] _keyId = [];

        public AesGcmSavedPasswordProtector(byte[]? key, ILogger<AesGcmSavedPasswordProtector> logger)
        {
            _key = key;
            if (key is not null)
            {
                _keyId = SHA256.HashData(key)[..KeyIdSize];
            }
            logger.LogInformation("Remembered passwords: {State}", key is null ? "off (SavedConnections:PasswordKey not set)" : "on");
        }

        public bool Enabled => _key is not null;
        ...
    }
```

Method bodies, as specified:

- `Protect`: throw `InvalidOperationException("Remembering passwords is not turned on.")` when `_key` is null. `var plaintext = Encoding.UTF8.GetBytes(password)`. Allocate `HeaderSize + plaintext.Length` bytes, write the version, the key id, then `RandomNumberGenerator.Fill` the nonce span. `using var aes = new AesGcm(_key, TagSize);` then `aes.Encrypt(nonce, plaintext, ciphertextSpan, tagSpan, AssociatedData(id, ownerId))`. `CryptographicOperations.ZeroMemory(plaintext)` in a `finally`.
- `IsCurrent`: `_key is not null && value.Length >= HeaderSize && value[0] == FormatVersion && value.AsSpan(1, KeyIdSize).SequenceEqual(_keyId)`.
- `Unprotect`: `null` unless `IsCurrent`. Decrypt into a new `byte[value.Length - HeaderSize]`, return `Encoding.UTF8.GetString`, `catch (CryptographicException)` returns `null` (`AuthenticationTagMismatchException` derives from it), and zero the plaintext buffer in a `finally`.
- `private static byte[] AssociatedData(Guid id, string ownerId) => Encoding.UTF8.GetBytes($"MDBNavigator saved connection password v1\n{id:D}\n{ownerId}");`
- A new `AesGcm` per call: it's cheap, and it avoids any question about sharing one instance across threads.

    && form.serverName.trim().toLowerCase() === target.serverName.trim().toLowerCase()

    && form.userName.trim() === target.userName.trim();

  if (reconnecting) {

### Remembered passwords

Off unless `SavedConnections:PasswordKey` is set. Then the connect dialog offers "Remember password" for a saved connection, and the server keeps that password encrypted with AES-GCM in the app database.

- The password never comes back to the browser. To connect with it, the UI sends the saved connection's id with an empty password, and the server decrypts it for that connect only.

- A wrong key (not base64, or not 32 bytes) stops startup.

## 6. Edge cases & don'ts

- **Never return the password or the encrypted bytes** in any DTO, error message or log. `SavedConnectionRequest` and `SavedConnectionInput` are records, and a record's generated `ToString()` prints every property, so both need the `PrintMembers` override (5.3, 5.8). Don't log `request.Input` anywhere.
- **Don't use Data Protection** (`IDataProtector`), even though it is already set up: see Decisions.
- **Don't trust the UI.** Every handler checks `_passwords.Enabled` itself, and connect checks `SameTarget` itself, even though the UI already hides the option and makes the field required.
- **Don't decrypt in the list or get handlers.** `HasPassword` uses `IsCurrent` only.
- **Don't derive the nonce** from the id or a counter, and don't reuse one: `RandomNumberGenerator.Fill` for each value.
- **Don't trim or otherwise change passwords.** Lengths are checked untrimmed, and an all-spaces password is a password.
- **Don't store a password on connect.** Only POST/PUT `savedConnections` store one (the UI calls them after a successful connect, as in 1.2b). Connect only reads.
- **Don't put the id into the domain `ConnectionSettings`.** That object is cached per connection, and the lookup belongs to the request.
- **Don't let a remembered-password connect skip anything.** It goes through `DbConnectionHelper.ConnectAsync`, so the connection guard, the failed-connect wait and the CAPTCHA apply. The resolve step runs before it and attempts no connection, so its 400/404 don't count as failed connects.
- **Wrong row, other user:** `FindAsync` filters by owner. A foreign id gives 404, the same as a missing one. Even if a value were copied into another user's row directly in the database, the associated data would make it fail to decrypt.
- **A typed password plus a `savedConnectionId`:** the typed one is used and the id is not looked up. A deleted entry's id with a typed password still connects.
- **PUT with `rememberPassword: true`, no password, and a changed server:** the password is dropped silently and the response says `hasPassword: false`. That isn't an error. The UI never sends this (a changed server makes the field required).
- **The key is removed:** `hasPassword` is `false` everywhere, the checkbox and Forget button are hidden, and the stored bytes stay. A PUT with `rememberPassword: false` still clears them, and so does the Forget endpoint, which works without the key.
- **Deleting an account** deletes its saved connections (1.2a), and with them their passwords. Nothing more to do.
- **No key in `appsettings*.json` or `launchSettings.json`**, not even an empty placeholder: it invites pasting a real key there.
- **Don't add a unit test project here.** Tests are roadmap 0.3. Verification is by requests and in the browser (section 8).
