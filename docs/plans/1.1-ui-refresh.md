# 1.1 UI refresh: theme tokens, dark mode and the restyled shell

## 1. Goal

Give the workspace the compact IDE look the owner chose ("B+" on the design canvas https://claude.ai/artifact/PkVfoV89yYv79zT7PJBFc4, top row), with a light and a dark theme built from Tailwind color tokens. Every query tab and the new query bar show which server and database the query runs on, with a color per server.

Roadmap: the first Phase 1 step (this plan adds steps 1.1 to 1.3 to `docs/ROADMAP.md`). Changes the root README "Features" list and the UI README "Source layout" and "Conventions". Approved by the owner on 2026-11-01.

**Before starting:** `git log --oneline -3` must show "Security headers (roadmap 0.2d)" or later. `git status` may show `MDBNavigator.API/appsettings.json` (the CAPTCHA default fix); leave that file alone. Anything else uncommitted: stop and ask the owner.

## 2. Decisions

- **Look: "B+"**: compact rows (24 px tree and grid rows), square-ish corners (3 px), blue accent, grey chrome bars, monospaced result grid. Not the roomy shadcn look.
- **No new dependencies.** Colors are CSS variables mapped to Tailwind utilities. Icons come from `react-icons/lu` (Lucide, already installed with react-icons 5.4.0). No shadcn/ui or Radix in this step; whether dialogs and menus move to Radix is decided in 1.2, when the connect dialog is rebuilt anyway.
- **System fonts** (owner's choice): no font packages. The CSP blocks Google Fonts, and the OFL font licence is not on the project's licence list.
- **Dark mode:** the user's choice from a button in the top bar, kept in `localStorage`; until they choose, the system setting is followed, live. Implemented with a `dark` class on `<html>`.
- **Color tokens, not palette classes.** After this step no `.tsx` file uses palette classes (`stone-700`, `red-600`, ...) or `dark:` variants. Each color has a role name (`bg-canvas`, `text-fg-muted`, `border-line`, ...) with a light and a dark value in `src/index.css`.
- **A color per server**, picked from a fixed palette of six by hashing `serverName:port:userName`, so it stays the same across reconnects and reloads. It shows in the tree (a square before the server name), as a 3 px strip on top of the query tab, and in the query bar. In 1.2 saved connections let users pick the color; this hash stays as the fallback. Two servers can get the same color; that is accepted.
  - **Changed after the first build (owner's review):** two connections to the same server got the same color and could not be told apart. Now the hash only picks the *preferred* color; `pickConnectionColor(connection, usedColors)` takes the next free color when an open connection already has it. The color is picked once in the connect reducer (`DatabaseServerConnection.color`, kept on reconnect), and the tree and `MainBar.queryTarget` read it from there, so it never changes while the connection is open. The snippets in §5.5, §5.8 and §5.9 show the first version.
- **Query tabs have two lines:** the title, and `server · database` below it. Untitled queries ("New Query for this database") are called `Query <n>`; generated ones keep their name (`public.users`).
- **Query bar** above the editor: Run, Stop, the server chip, the database chip, then `user@host:port` on the right. The chips only display in this step; switching a tab's server or database comes with 1.2. Run and Stop move here from below the editor; Stop is enabled only while the query runs.
- **The "Servers" root node is hidden.** The sidebar gets a header, "Connections", with a "+" button that opens the connect dialog (the same action as the old "New Connection" menu item on the root node).
- **Not built from the mockup** (no feature behind them yet): the activity bar, the search box, the Saved and History buttons, result-set tabs, Copy, Export, row filter. They come with later steps.
- **Monaco:** own light and dark themes whose background matches the app; minimap off; 14 px system monospace. Base UI text is 14 px, the result grid 13 px (raised by 1 px after the first build, at the owner's request).
- **Auth pages, account page and dialogs** only get their colors swapped to tokens, so they work in dark mode. Their layout stays as it is.
- **Known limitation, accepted:** the ALTCHA widget keeps its own light styling in dark mode. Turnstile follows the system setting by itself.

### 5.4 Theme context

`src/contexts/theme/theme.ts`:

```ts
export type Theme = 'light' | 'dark';

const STORAGE_KEY = 'mdbnavigator.theme';

// The user's explicit choice; null means "follow the system setting".
export function getStoredTheme(): Theme | null {
  try {
    const value = localStorage.getItem(STORAGE_KEY);
    return value === 'light' || value === 'dark' ? value : null;
  } catch {
    // Storage blocked (private mode, a browser policy): follow the system setting.
    return null;
  }
}

export function storeTheme(theme: Theme): void {
  try {
    localStorage.setItem(STORAGE_KEY, theme);
  } catch {
    // Not remembered for the next visit, but still applied now.
  }
}

export function systemDarkQuery(): MediaQueryList {
  return window.matchMedia('(prefers-color-scheme: dark)');
}

export function initialTheme(): Theme {
  return getStoredTheme() ?? (systemDarkQuery().matches ? 'dark' : 'light');
}

// The .dark class switches the color variables in index.css.
export function applyTheme(theme: Theme): void {
  document.documentElement.classList.toggle('dark', theme === 'dark');
}
```

`src/contexts/theme/ThemeContextProvider.tsx`:

```tsx
import { useCallback, useEffect, useMemo, useState } from "react";
import { applyTheme, getStoredTheme, initialTheme, storeTheme, systemDarkQuery, Theme } from "./theme";
import { ThemeContext } from "./useTheme";

// Light or dark: the user's choice from the top bar (kept in localStorage), otherwise the system setting.
export default function ThemeContextProvider({ children }: React.PropsWithChildren) {
  const [theme, setTheme] = useState<Theme>(initialTheme);

  // Until the user picks a theme, follow the system setting as it changes (for example a dark mode at night).
  useEffect(() => {
    const query = systemDarkQuery();
    function handleChange() {
      if (!getStoredTheme()) {
        setTheme(query.matches ? 'dark' : 'light');
      }
    }
    query.addEventListener('change', handleChange);
    return () => query.removeEventListener('change', handleChange);
  }, []);

  useEffect(() => {
    applyTheme(theme);
  }, [theme]);

  const toggleTheme = useCallback(() => {
    const next: Theme = theme === 'dark' ? 'light' : 'dark';
    storeTheme(next);
    setTheme(next);
  }, [theme]);

  const value = useMemo(() => ({ theme, toggleTheme }), [theme, toggleTheme]);

  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>;
}
```

```ts
import { ConnectionBase } from "../models/connect/connectionBase";

// Each server gets a color for its tree node, query tabs and query bar, so it is clear where a query runs.
// It comes from the server's address, so it stays the same across reconnects and reloads.
// (Saved connections will let the user choose; this stays the fallback.)
const CONNECTION_COLORS = ['#16a34a', '#ea580c', '#7c3aed', '#0284c7', '#db2777', '#ca8a04'];

export const UNKNOWN_CONNECTION_COLOR = '#8b929c';

export function connectionColor(connection: ConnectionBase): string {
  const key = `${connection.serverName}:${connection.port ?? ''}:${connection.userName}`.toLowerCase();
  let hash = 0;
  for (let i = 0; i < key.length; i++) {
    hash = (hash * 31 + key.charCodeAt(i)) >>> 0;
  }
  return CONNECTION_COLORS[hash % CONNECTION_COLORS.length];
}

// user@host:port, as shown in the query bar.
export function connectionAddress(connection: ConnectionBase): string {
  return `${connection.userName}@${connection.serverName}${connection.port ? `:${connection.port}` : ''}`;
}
```

## 6. Edge cases & don'ts

- **No new npm packages.** Everything uses React, Tailwind and `react-icons/lu`. If an icon name in this plan doesn't exist, stop and ask (all were checked against react-icons 5.4.0).
- **No palette classes and no `dark:` in `.tsx` files** after step 10 (the grep in §8.3 must be empty). `bg-black/40` (the dialog backdrop) is the one allowed literal color.
- **No inline `<script>` anywhere**, and no `style` with `url(...)`: the CSP allows inline styles, not inline scripts. The theme is applied in `main.tsx` for that reason.
- **Don't change logic** in contexts, reducers, services or the hub. The only behavior changes are the ones in §2: Run and Stop placement, the hidden root node, untitled tab names, the theme.
- **Don't delete** the `NodeType.Servers` branch in `DatabaseContextMenu.tsx`: it becomes unreachable, but removing it is not part of this step.
- **Keep non-component exports out of `.tsx` files** (see §4), or lint fails.
- **The `Tab` component's `about` attribute and `key`** stay as they are; only `TabProps` grows.
- **ToastContainer** keeps `theme='colored'`.
- **Don't touch** `vite.config.ts`, `eslint.config.js`, the API, or `MDBNavigator.API/appsettings.json`.
- **Test runs must not touch** the owner's app database (`MDBNavigator.API/data/mdbnavigator.db`), the owner's Vite dev server on port 3000, or Visual Studio's API. Use a scratch build, port 5199 and a throwaway SQLite path (§8).
- **The owner's PostgreSQL is read-only:** connect and `select` only. Credentials are in `mdb-navigator-ui/.env.development.local`. If it can't be reached, stop and report; don't start or create databases.
- **If something in this plan doesn't compile or looks wrong, stop and ask.** Don't improvise a different design.
- Plain English in comments and docs, no em dashes.
