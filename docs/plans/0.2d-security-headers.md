# 0.2d Security headers

## 1. Goal

Every response carries security headers: a Content Security Policy built from the settings, HSTS, and the usual small ones. Kestrel's `Server` header goes away.

Roadmap step 0.2d (`docs/ROADMAP.md`). Changes the README's "Security status" note and adds a README section "Security headers"; one bullet in `docs/specs/authentication.md`. Approved by the owner on 2026-11-01.

**Before starting:** `git log --oneline -3` must show the 0.2c commit ("Optional CAPTCHA (roadmap 0.2c)"). If 0.2c is still uncommitted (`git status` shows its files), stop and ask the owner to commit it first.

## 2. Decisions

- **Own middleware, no package** (not NetEscapades.AspNetCore.SecurityHeaders): only a few headers, no dependency, and every line is explainable for the portfolio.
- **HSTS through ASP.NET Core's built-in `AddHsts`/`UseHsts`**, not in our middleware: it already sends the header only over HTTPS and skips `localhost`, `127.0.0.1` and `[::1]`. One year, **no** `includeSubDomains`, **no** `preload` (self-hosters may have plain-HTTP services on sibling subdomains; preload is hard to undo). Not in Development.
- **The CSP is built once at startup from `CaptchaOptions`**: Cloudflare's origin is allowed only when `Captcha:Provider` is `Turnstile`.
- **`style-src` allows `'unsafe-inline'`**: Monaco and react-toastify set inline styles. Scripts stay strict: no `'unsafe-inline'`, no `'unsafe-eval'`, no `blob:`.
- **Headers go on every response** (API JSON, errors, static files, the SPA), in every environment except HSTS (above). They are set before the rest of the pipeline runs, so error responses from `ExceptionMiddleware` carry them too.
- **No settings and no report-only switch** for now.
- **Development:** the UI comes from the Vite dev server, which needs inline scripts for hot reload, so the CSP doesn't cover the dev page. Nothing is added to Vite.

## 5. Contracts

### `SecurityHeadersMiddleware.cs`

```csharp
using MDBNavigator.Application.Common;

namespace MDBNavigator.API.Middleware
{
    // Headers that tell the browser to be strict with this site (README "Security headers"). Set before the rest of
    // the pipeline runs, so every response carries them: the UI's files, API answers and error responses.
    // HSTS is not here: ASP.NET Core's UseHsts already sends it only over HTTPS and not for localhost.
    public class SecurityHeadersMiddleware
    {
        private readonly RequestDelegate _next;
        private readonly string _contentSecurityPolicy;

        public SecurityHeadersMiddleware(RequestDelegate next, CaptchaOptions captchaOptions)
        {
            _next = next;
            _contentSecurityPolicy = BuildContentSecurityPolicy(captchaOptions);
        }

        public Task InvokeAsync(HttpContext context)
        {
            var headers = context.Response.Headers;
            headers["Content-Security-Policy"] = _contentSecurityPolicy;
            headers["X-Content-Type-Options"] = "nosniff";
            headers["Referrer-Policy"] = "strict-origin-when-cross-origin";
            headers["Cross-Origin-Opener-Policy"] = "same-origin";
            headers["Permissions-Policy"] = "camera=(), microphone=(), geolocation=()";
            return _next(context);
        }

        // Built once at startup. With Turnstile, Cloudflare's script and iframe are allowed; otherwise nothing outside
        // this origin is.
        private static string BuildContentSecurityPolicy(CaptchaOptions captcha) { ... }
    }
}
```

`BuildContentSecurityPolicy` returns exactly these strings (directives joined with `"; "`, in this order). Add a short *why* comment for `style-src` (Monaco and toasts set inline styles; inline styles can't run code) and for `worker-src` (Monaco's and ALTCHA's workers are bundled files, never `blob:` URLs).

Provider `None` or `Altcha`:
```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'; worker-src 'self'; frame-src 'none'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

Provider `Turnstile` (only `script-src` and `frame-src` differ):
```
default-src 'self'; script-src 'self' https://challenges.cloudflare.com; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'; worker-src 'self'; frame-src https://challenges.cloudflare.com; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

```markdown
### Security headers

Every response carries headers that tell the browser to be strict with this site. They are set in `SecurityHeadersMiddleware`; Kestrel's `Server` header is removed.

| Header | Value | Why |
|---|---|---|
| `Content-Security-Policy` | see below | Only the app's own scripts run, so injected script can't, even if a bug lets some in. |
| `Strict-Transport-Security` | `max-age=31536000` | Browsers use only HTTPS for a year. Sent only over HTTPS, not in Development and not for `localhost`. No `includeSubDomains` or `preload`: other services on sibling subdomains may still use HTTP, and a preload entry is hard to take back. |
| `X-Content-Type-Options` | `nosniff` | The browser keeps to the declared content type, so a JSON or text answer is never run as a script. |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Other sites see only the origin, never paths or query strings (which may hold email confirmation codes). |
| `Cross-Origin-Opener-Policy` | `same-origin` | A page of another site that this app opens, or that opens it, can't reach its window. |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` | Browser features the app never uses stay off. |

The Content Security Policy:

- `default-src`, `connect-src` (the API and the SignalR WebSocket) and `worker-src` are `'self'`. Monaco's and ALTCHA's workers are bundled files, never `blob:` URLs. Images and fonts may also be `data:` URLs.
- `script-src 'self'`: no inline scripts and no `eval`. With `Captcha:Provider = Turnstile`, Cloudflare's `https://challenges.cloudflare.com` is allowed for its script and its iframe (`frame-src`, otherwise `'none'`).
- `style-src 'self' 'unsafe-inline'`: Monaco and the notifications set inline styles. Inline styles can't run code, so this is a small concession.
- `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, and `frame-ancestors 'none'`, so no other site can show the app inside a frame (against clickjacking).

In development the UI comes from the Vite dev server, which needs inline scripts for hot reload, so the policy only covers the UI when the API serves the built files. A reverse proxy in front of the app shouldn't add these headers a second time.
```

## 6. Edge cases & don'ts

- **Don't loosen the policy to make something work**: no `'unsafe-eval'`, no `'unsafe-inline'` in `script-src`, no `blob:`, no `*` or other hosts. If the browser test shows a violation, **stop and report it** (the exact console message and what was being done) instead of changing the policy.
- The built bundle contains one `blob:` string. If it causes a violation, that is the "stop and report" case above.
- Don't add `X-Frame-Options`, `X-XSS-Protection` or `Expect-CT` (the first is covered by `frame-ancestors`, the others are obsolete).
- Don't add settings, a report-only mode, or anything to `vite.config.ts`.
- Don't change `ExceptionMiddleware`, the HTTPS redirection block, CORS (there is none) or anything in `mdb-navigator-ui/src`.
- Don't use `context.Response.OnStarting`; set the headers before `_next`, as in the contract.
- Test runs must not touch the owner's app database (`MDBNavigator.API/data/mdbnavigator.db`) or the owner's Vite dev server on port 3000. Use a throwaway SQLite path and ports 5199/5198 (see §8).
- The owner's PostgreSQL is read-only: connecting and `select` only. Its credentials are in `mdb-navigator-ui/.env.development.local`.
- Browser-test gotchas from 0.2c: the ALTCHA checkbox is covered by the widget's own SVG, so click it with `{ force: true }`. Turnstile renders its iframe in a closed shadow root, so detect it with `page.frames()` (a frame whose URL contains `challenges.cloudflare.com`), not a CSS selector.
- Plain English in comments and docs, no em dashes.
