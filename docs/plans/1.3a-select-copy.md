# 1.3a Result grid: column types, tests, select and copy

## 1. Goal

The result grid gets a selection (a cell range, whole rows, whole columns, everything) with mouse and keyboard, and copies it as tab-separated text. Two foundations for all of 1.3 come with it: result columns carry a database-neutral type, and the UI gets its first unit tests (Vitest).

Roadmap step 1.3a (`docs/ROADMAP.md`), the first of four (1.3a–1.3d), all built on the branch `1.3-result-grid` and committed by the owner once, after 1.3d. Changes these docs: root `README.md` ("Features", "Streaming query results", "Development"), `mdb-navigator-ui/README.md` ("Scripts", "Source layout", the last paragraph of "How a query runs in the UI", "Conventions"), `docs/ROADMAP.md` (the 1.3 row), `CLAUDE.md` ("Building and checking", "Conventions"). Mock agreed with the owner: https://claude.ai/artifact/8YCZfS9K3puEqj7Gigjg5e (board "1.3a Select and copy").

**Before starting:** `git branch --show-current` must print `1.3-result-grid`, and `git status --short` must show nothing but the four `docs/plans/1.3*.md` files. Otherwise stop and ask.

## 2. Decisions

Agreed with the owner on 2026-11-13:

1. **Our own grid stays** (TanStack Virtual). No grid library.
2. **Selection is one rectangle of cells**, like Excel: click, Shift+click, drag. A row number selects the row, a header selects the column, the corner cell and Ctrl+A select everything. There is no Ctrl+click multi-selection.
3. **Copy is tab-separated text** (pastes into Excel and Sheets). Ctrl+C copies the values, Ctrl+Shift+C adds a header row. A right-click menu offers the same.
4. **Column types are database-neutral.** Each result column carries a `category` (`Number`, `Text`, `Boolean`, `DateTime`, `Json`, `Binary`, `Other`) and a `dataTypeName`. The UI's behavior reads only `category`. `dataTypeName` is whatever the database calls the type (`jsonb`, `numeric(10, 2)`, later `nvarchar`); the UI shows it and never interprets it. The two .NET-name fields (`fieldType`, `fieldDataTypeName`) are removed. A shared mapper derives the category from the .NET type, which every provider has; a provider only corrects what its database knows better (PostgreSQL: `json` and `jsonb` arrive as strings).
5. **Vitest** (MIT, dev only) with unit tests for the new pure functions. This starts roadmap step 0.3a.
6. **One commit at the end of 1.3**, by the owner. Never commit.

Decided by the planner (small, reversible):

- **NULL copies as an empty field.** A single copied cell is the exact value with no quoting. In a multi-cell copy a field is quoted (quotes doubled) only when it contains a tab or line break or starts with `"`, which is what Excel expects; JSON text therefore stays unquoted.
- **A column or "everything" selection is fixed when it is made.** Rows that arrive later in a running query are not added to it.
- **Drag does not auto-scroll.** Select further with Shift+click or Shift+arrows.
- **The status bar shows the selection size** when more than one cell is selected.
- **A header click selects the column.** Sorting (1.3c) gets its own button inside the header, as in DBeaver and pgAdmin.

### What we found in the code

- `DataGrid` is keyed per result set by its parent, and a result set's id contains the execution id, so a new run remounts the grid and the selection resets by itself.
- SignalR already serializes enums as strings (`AddJsonProtocol` with `JsonStringEnumConverter` in `InfrastructureServiceRegistration.cs`), so `category` arrives as `"Number"`.
- `ui/contextMenu/Menus.tsx` does not keep a menu inside the window. The grid sits at the bottom of the window, so the grid's menu clamps its own position.
- Rows have a fixed height, so "scroll the cell into view" is exact arithmetic and does not need the virtualizer.

`MDBNavigator.Application/Common/DbTypeCategories.cs`:

```csharp
using MDBNavigator.Domain.Enums;
using System.Numerics;

namespace MDBNavigator.Application.Common
{
    // The category a .NET value type implies. Every database driver reports .NET types, so this part is shared;
    // a provider calls it and then corrects only what its database knows better (PostgreSQL: json arrives as a string).
    public static class DbTypeCategories
    {
        public static DbTypeCategory FromClrType(Type type)
        {
            type = Nullable.GetUnderlyingType(type) ?? type;

            if (type == typeof(bool)) return DbTypeCategory.Boolean;
            if (type == typeof(string) || type == typeof(char)) return DbTypeCategory.Text;
            if (type == typeof(byte[])) return DbTypeCategory.Binary;
            if (type == typeof(DateTime) || type == typeof(DateTimeOffset) || type == typeof(DateOnly) || type == typeof(TimeOnly))
                return DbTypeCategory.DateTime;
            if (type == typeof(byte) || type == typeof(sbyte) || type == typeof(short) || type == typeof(ushort)
                || type == typeof(int) || type == typeof(uint) || type == typeof(long) || type == typeof(ulong)
                || type == typeof(decimal) || type == typeof(float) || type == typeof(double) || type == typeof(BigInteger))
                return DbTypeCategory.Number;

            return DbTypeCategory.Other;
        }
    }
}
```

### 5.5 `selection.ts`

All indexes are positions in the grid as displayed: row 0 is the first displayed row, column 0 the first data column (the row-number column is not a column here).

```ts
export interface CellPosition { row: number; column: number; }

// A rectangle of cells between two corners, both included. anchor is the active cell (where the selection began);
// focus is the corner that Shift+click, dragging and Shift+arrows move.
export interface GridSelection { anchor: CellPosition; focus: CellPosition; }

export interface SelectionRange { top: number; bottom: number; left: number; right: number; }

export interface SelectionSize { rows: number; columns: number; }

export type MoveKey = 'ArrowUp' | 'ArrowDown' | 'ArrowLeft' | 'ArrowRight' | 'Home' | 'End' | 'PageUp' | 'PageDown';

export function rangeOf(selection: GridSelection): SelectionRange
export function sizeOf(selection: GridSelection): SelectionSize
export function isInRange(range: SelectionRange, row: number, column: number): boolean
export function selectCell(position: CellPosition): GridSelection
export function extendTo(selection: GridSelection, position: CellPosition): GridSelection
export function selectRows(fromRow: number, toRow: number, columnCount: number): GridSelection
export function selectColumns(fromColumn: number, toColumn: number, rowCount: number): GridSelection
export function selectAll(rowCount: number, columnCount: number): GridSelection
export function isMoveKey(key: string): key is MoveKey
export function moveSelection(
  selection: GridSelection,
  key: MoveKey,
  modifiers: { extend: boolean; jump: boolean },
  rowCount: number,
  columnCount: number,
  pageRows: number,
): GridSelection
```

- `selectRows(from, to, columnCount)`: anchor `{ row: from, column: 0 }`, focus `{ row: to, column: columnCount - 1 }`. `selectColumns(from, to, rowCount)`: anchor `{ row: 0, column: from }`, focus `{ row: rowCount - 1, column: to }`. `selectAll`: anchor `{0,0}`, focus the last cell.
- `moveSelection`: the cell that moves is `focus` when `extend`, else `anchor`. The target, clamped to the grid:
  - Arrows: one step; with `jump`, to the first or last row or column in that direction.
  - `Home`/`End`: first/last column of the same row; with `jump`, the first cell of the grid / the last cell of the grid.
  - `PageUp`/`PageDown`: `pageRows` rows.
  - Result: `extend` → `{ anchor, focus: target }`; otherwise `{ anchor: target, focus: target }`.
- Callers guarantee `rowCount > 0` and `columnCount > 0`.

`selection.test.ts`: `rangeOf` with the focus above and left of the anchor; `sizeOf`; `isInRange` on the edges and just outside; `extendTo` keeps the anchor; `selectRows`, `selectColumns`, `selectAll`; `moveSelection`: each arrow, clamping at all four edges, `jump` arrows, `Home`/`End` with and without `jump`, `PageDown` clamped at the last row, `extend` moves only the focus, and a move without `extend` from a range collapses to one cell next to the anchor.

### 5.6 `gridGeometry.ts`

```ts
export const ROW_HEIGHT = 24;
export const HEADER_HEIGHT = 28;

// Left edge of each data column in the grid's content, after the row-number column.
export function columnOffsets(widths: number[], rowNumberWidth: number): number[]

export interface Viewport { scrollTop: number; scrollLeft: number; clientWidth: number; clientHeight: number; }

// The scroll position that brings a cell fully into view, moving as little as possible. The header stays on top
// and the row-number column on the left, so the cell must clear both.
export function scrollToReveal(
  viewport: Viewport,
  cell: { top: number; left: number; width: number; height: number },
  sticky: { top: number; left: number },
): { scrollTop: number; scrollLeft: number }

// Keeps a menu of the given size inside the window, 8px from its edges.
export function clampMenuPosition(
  x: number, y: number,
  menu: { width: number; height: number },
  page: { scrollX: number; scrollY: number; innerWidth: number; innerHeight: number },
): { x: number; y: number }
```

- `scrollToReveal`, vertically: if `cell.top < scrollTop + sticky.top` → `scrollTop = cell.top - sticky.top`; else if `cell.top + cell.height > scrollTop + clientHeight` → `scrollTop = cell.top + cell.height - clientHeight`; else unchanged. Horizontally the same with `left`, `width`, `sticky.left`, `clientWidth`. Never below 0. A cell wider than the visible area aligns its left edge.
- `clampMenuPosition`: `x = max(scrollX + 8, min(x, scrollX + innerWidth - width - 8))`, the same for `y`.

`gridGeometry.test.ts`: `columnOffsets([100, 50], 44)` is `[44, 144]`; `scrollToReveal` for a cell already visible (unchanged), hidden under the header, below the bottom, hidden under the row-number column, right of the edge, and wider than the viewport; `clampMenuPosition` inside (unchanged), past the right edge, past the bottom, and with a scrolled page.

`DataGrid.tsx` imports `ROW_HEIGHT` and `HEADER_HEIGHT` from here (its own `ROW_HEIGHT` constant goes away; the header keeps `h-7`, which is 28px).

### 5.7 `clipboardText.ts`

```ts
// The selected cells as text for the clipboard. getRow returns the displayed row at an index.
```

- One cell and `withHeaders` false: `cellToText(value)` exactly, no quoting.

### 5.8 `utils/clipboard.ts`

```ts
// navigator.clipboard exists only on HTTPS and localhost; the caller tells the user when this fails.
export async function copyText(text: string): Promise<void> {
  if (!navigator.clipboard) {
    throw new Error('The clipboard is not available');
  }
  await navigator.clipboard.writeText(text);
}
```

(If lint flags the check as always false, keep the behavior with a type-safe test such as `!('clipboard' in navigator)`.)

### 5.10 `DataGrid.tsx`

```ts
export interface DataGridColumn {
  name: string;
  // The database's own type name; shown in the header tooltip.
  typeName: string;
  category: DbTypeCategory;
}

interface Props {
  columns: DataGridColumn[];
  rows: CellValue[][];
  // The grid produces the text; the caller owns the clipboard and its error message.
  onCopyText: (text: string) => void;
  // The size of the selection, or null when nothing is selected.
  onSelectionChange?: (size: SelectionSize | null) => void;
}
```

Keep the virtualizer, the width measuring and the look. Changes:

- **Derived values:** `rowCount = rows.length`; `getRow = (index: number) => rows[index]`; `offsets = columnOffsets(widths, rowNumberWidth)`; `range = selection ? rangeOf(selection) : null`. Later steps change `rowCount` and `getRow` only, so every new piece of code goes through them, never through `rows` directly.
- **State:** `selection: GridSelection | null`, `menu: CoordPosition | null`. A ref `drag: 'cells' | 'rows' | null`.
- **`select(next: GridSelection | null)`:** `setSelection(next)` and `onSelectionChange?.(next ? sizeOf(next) : null)`. Every selection change goes through it, from event handlers only (no effect reports the selection).
- **Scroll container:** add `tabIndex={0}`, `role="grid"`, `aria-label="Query result"`, `aria-rowcount={rowCount}`, `aria-colcount={columns.length}`, `aria-multiselectable="true"`, and the classes `select-none outline-none` (the browser's own text selection would fight ours; copying goes through Ctrl+C). `onKeyDown`, `onScroll` (closes the menu when one is open).
- **Header:** `role="row"`; cells `role="columnheader"`. The corner cell (above the row numbers) selects everything on click (`aria-label="Select all"`, `cursor-pointer`). A header cell's `onPointerDown` (button 0): with Shift and a selection, `selectColumns(selection.anchor.column, index, rowCount)`; otherwise `selectColumns(index, index, rowCount)`. Nothing when `rowCount === 0`. Header cells of columns inside `range` get `bg-selected text-on-selected`. Tooltip: `` `${column.name} (${column.typeName})` ``. Header cells get `cursor-pointer`.
- **Rows:** `role="row"`, placed with `top: item.start` in place of the `transform` (a transform makes each row its own stacking context, and the row number's `z-[1]` could then not lift it above the selection outline). The row-number cell gets `data-row={item.index}`, `z-[1]` (it must stay above the selection outline), and `bg-selected text-on-selected` in place of `bg-surface text-fg-muted` when its row is inside `range`. Each data cell gets `role="gridcell"`, `data-row`, `data-col`, `aria-selected`, and `bg-selected` when it is inside `range` and is not the anchor cell (the anchor stays on the canvas color, as in Excel).
- **Selection outline:** inside the rows container (`relative`), after the rows: `<div aria-hidden="true" className="pointer-events-none absolute border-2 border-accent" style={{ top: range.top * ROW_HEIGHT, left: offsets[range.left], width: offsets[range.right] + widths[range.right] - offsets[range.left], height: (range.bottom - range.top + 1) * ROW_HEIGHT }} />`.
- **Pointer handling, delegated on the rows container** (no handler per cell). Find the cell with `(e.target as HTMLElement).closest<HTMLElement>('[data-row]')`; `data-col` is absent on a row-number cell.
  - `onPointerDown`, button 0 only. Row-number cell: `drag = 'rows'`; with Shift and a selection `selectRows(selection.anchor.row, row, columns.length)`, else `selectRows(row, row, columns.length)`. Data cell: `drag = 'cells'`; with Shift and a selection `extendTo(selection, position)`, else `selectCell(position)`. Then `scrollRef.current?.focus({ preventScroll: true })`.
  - `onPointerOver` while `drag` is set and a selection exists: `'rows'` → `selectRows(selection.anchor.row, row, columns.length)`; `'cells'` over a data cell → `extendTo(selection, position)`. Skip the update when the focus would not change.
  - An effect bound once adds `pointerup` and `pointercancel` listeners on `window` that set `drag.current = null`, and removes them on unmount.
  - `onContextMenu`: `preventDefault()`. Over a data cell outside `range` (or with no selection): `selectCell` it first. Over a row number whose row is outside `range`: select that row first. With no selection and no cell: do nothing. Otherwise open the menu at `clampMenuPosition(e.pageX, e.pageY, GRID_MENU_SIZE, { scrollX: window.scrollX, scrollY: window.scrollY, innerWidth: window.innerWidth, innerHeight: window.innerHeight })`.
- **Keyboard** (`onKeyDown` on the scroll container; `mod = e.ctrlKey || e.metaKey`). Ignore everything when `rowCount === 0` or there are no columns. Call `preventDefault()` for every key handled.
  - `mod` + `a`: `selectAll(rowCount, columns.length)`.
  - `mod` + `c` (compare `e.key.toLowerCase()`): copy; with Shift, copy with headers. Nothing without a selection.
  - `Escape`: close the menu if it is open, else clear the selection.
  - A move key (`isMoveKey(e.key)`): without a selection, select the cell at the first visible row (`virtualizer.range?.startIndex ?? 0`; `getVirtualItems()` would start at the overscan rows above it) and column 0. Otherwise `moveSelection(selection, key, { extend: e.shiftKey, jump: mod }, rowCount, columns.length, pageRows)`, with `pageRows = Math.max(1, Math.floor((container.clientHeight - HEADER_HEIGHT) / ROW_HEIGHT) - 1)`. Then reveal the cell that moved (`focus` when Shift is held, else `anchor`): compute `scrollToReveal(viewport, { top: HEADER_HEIGHT + row * ROW_HEIGHT, left: offsets[column], width: widths[column], height: ROW_HEIGHT }, { top: HEADER_HEIGHT, left: rowNumberWidth })` and assign `scrollTop`/`scrollLeft` on the container when they differ.
- **Copy:** `onCopyText(selectionToText(range, columns.map(c => c.name), getRow, withHeaders))`.
- **Menu:** `{menu && <GridContextMenu position={menu} onClose={...} onCopy={...} onCopyWithHeaders={...} onSelectAll={...} />}`. Closing it puts the focus back on the scroll container.
- **A selection can point past the rows only after the grid remounts**, which resets it, so no clamping is needed in this step.

```ts
const [selection, setSelection] = useState<{ resultSetId: string; size: SelectionSize } | null>(null);

function handleSelectionChange(resultSetId: string, size: SelectionSize | null) {
  setSelection(previous => size ? { resultSetId, size } : (previous?.resultSetId === resultSetId ? null : previous));
}

const selectionSize = selection && resultSets.some(rs => rs.id === selection.resultSetId) ? selection.size : null;
```

(`resultSets` comes from the `useDatabaseCommandSelector` call that is already there.) Pass `onSelectionChange={handleSelectionChange}` to the result view and `selection={selectionSize}` to the status bar. Hooks stay above the early `return null`.

## 6. Edge cases & don'ts

- **Don't add any dependency other than `vitest`.** No grid, clipboard or hotkey library, no jsdom.
- **Don't read `dataTypeName` for behavior**, in this step or later. Only `category`.
- **Don't keep the old field names** as aliases, on either side.
- **Don't add a handler per cell.** Thousands of cells are on screen; the rows container delegates.
- **Don't report the selection from an effect.** `select()` does it in the event handler.
- **Don't use `document.execCommand('copy')`** as a fallback; the toast explains the limit.
- **Don't truncate copied text.** `formatCell` cuts at 1,000 characters for display only; `cellToText` never cuts.
- **An empty result** (columns, no rows): header clicks, Ctrl+A and arrow keys do nothing.
- **Rows arriving while a selection exists:** the selection keeps its indexes. Nothing to do.
- **Right-click inside the selection** keeps it; outside, it selects that cell first.
- **Ctrl+Shift+C** must call `preventDefault()`, or the browser opens its developer tools.
- **Several result sets** are still stacked in this step (tabs come in 1.3d). Each grid has its own selection; the status bar shows the one changed last.
- **Lint has zero warnings:** no `!` where a guard is easy, exhaustive deps, no floating promises (`void` the copy).
- **The API must be restarted** to send the new fields. With an old API still running, columns have no `category`; that is expected until the restart, and nothing in the UI should try to support both shapes.
- **Never commit.**
