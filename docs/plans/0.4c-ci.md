# 0.4c CI

## 1. Goal

A GitHub Actions workflow that checks every push and pull request: the backend builds with warnings as errors and all its tests pass, the UI passes its type check, lint, tests and build, and the Docker image builds and starts. The README shows the result as a badge.

Roadmap step **0.4c** ([ROADMAP.md](../ROADMAP.md), "0.4 Docker").

Docs it changes: `README.md` (a badge, one sentence in "Development"), `docs/ROADMAP.md` (plan link), the owner's local `CLAUDE.md` (one bullet).

## 2. Decisions

- **One workflow, three jobs that run side by side:** `backend`, `ui`, `image`. A failure names the part that broke.
- **The image is built but not pushed.** Publishing was put off on 2026-11-15; no registry login, no package permissions.
- **The smoke tests run in CI as they are:** GitHub's Linux runners have Docker, which is all Testcontainers needs.
- **The image job also starts the container** and waits for `GET /health`, so an image that builds but can't start fails the run.
- **The sample database image (0.4b) is built too**, in the image job: its pinned download and checksums are exactly the kind of thing that breaks quietly.
- **Least privilege:** `permissions: contents: read` for the whole workflow.
- **Runs on pushes to `master` and on pull requests.** A newer run for the same branch cancels the older one.
- **The SDK and Node versions come from the repository:** `global.json` for .NET, Node 22 as in the Dockerfile.
- **Actions are referenced by their current major version tag.** Look each one up when writing the file; don't copy version numbers from memory.
- **It cannot be run locally.** What can be checked here is that the file is valid and that every command in it works on this machine; the first real run happens when the owner pushes.

## 5. Contracts

### `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
    branches: [master]
  pull_request:

permissions:
  contents: read

# A newer push to the same branch or pull request makes the older run pointless.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  backend:
    name: Backend (build and tests)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<major>
      - uses: actions/setup-dotnet@<major>
        with:
          global-json-file: global.json
      - name: Restore
        run: dotnet restore MDBNavigator.slnx
      # Release treats warnings as errors.
      - name: Build
        run: dotnet build MDBNavigator.slnx -c Release --no-restore
      # The API smoke tests start PostgreSQL in a container; the runner has Docker.
      - name: Test
        run: dotnet test MDBNavigator.slnx -c Release --no-build --logger "trx" --results-directory test-results
      - name: Keep the test results
        if: always()
        uses: actions/upload-artifact@<major>
        with:
          name: backend-test-results
          path: test-results

  ui:
    name: UI (check, tests, build)
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: mdb-navigator-ui
    steps:
      - uses: actions/checkout@<major>
      - uses: actions/setup-node@<major>
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: mdb-navigator-ui/package-lock.json
      - run: npm ci
      # Type check, and lint with zero warnings allowed.
      - run: npm run check
      - run: npm test
      - run: npm run build

  image:
    name: Docker images
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<major>
      - name: Build the app image
        run: docker build -t mdbnavigator:ci .
      - name: Build the sample database image
        run: docker build -t mdbnavigator-sample-db:ci docker/sample-db
      # An image that builds but can't start should fail here, not on a server.
      - name: Start the app and wait for /health
        run: |
          docker run -d --name app -p 8080:8080 \
            -e Auth__Admin__Email=ci@example.test -e Auth__Admin__Password=ci-only-password \
            mdbnavigator:ci
          for i in $(seq 1 30); do
            if curl -fsS http://localhost:8080/health; then echo; exit 0; fi
            sleep 2
          done
          docker logs app
          exit 1
```

- Replace every `<major>` with that action's current major version tag (for example `v5`), looked up now: `gh api repos/actions/checkout/releases/latest --jq .tag_name`, and the same for `actions/setup-dotnet`, `actions/setup-node`, `actions/upload-artifact`. Use the major part only (`v5`, not `v5.0.1`).
- If `actions/setup-dotnet` at that version has no `global-json-file` input, use `dotnet-version: 10.0.x` and say so.
- If the solution-level `dotnet restore`/`build`/`test` of a `.slnx` file fails locally for a reason that is about the CLI, not the code, stop and report; don't swap in per-project commands on your own.

## 6. Edge cases & don'ts

- **Don't push, don't open a pull request, don't trigger a workflow run.** The owner commits and pushes; the first run is theirs to watch.
- **Don't add secrets, registry logins, `packages: write` or any other permission.**
- **Don't change `cla.yml`.**
- **Don't pin actions to a version from memory.** Look them up (section 5).
- **The repository's default branch is `master`.**
- **Credentials in the workflow are throwaway values for a container that lives for seconds**; they are the only ones allowed in the file.
- **LF line endings** for the workflow file.
- **Don't change application code or tests** to make a command pass. If a command of the workflow fails locally, report it.
