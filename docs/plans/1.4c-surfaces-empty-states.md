# 1.4c UI polish: surfaces, identity, empty states

## 1. Goal

Give the light theme tones that can be told apart, show a query tab's server and database first in its status bar, and fill the places that are blank today: the workspace with no query open, the result pane before a run, after statements that return no rows, and after a failed statement.

Roadmap step 1.4c, the last of the UI polish. Changes these docs: root `README.md` ("Features", "Development"), `docs/ROADMAP.md`.

UI only: no server file changes, no new packages.

**Before starting:** step 1.4b is committed (`git log` shows "UI polish: one style for form controls (roadmap 1.4b)") and `git status --short` shows nothing but this plan. Otherwise stop and ask.

## 2. Decisions

### Agreed with the owner on 2026-11-14

From the mock at https://claude.ai/artifact/Q6Qqc3fK9sHmzp9LLr6kzZ (boards 1b, 2a, 3a–3d):

1. **Light theme tones** as in board 1b: sidebar `#f4f5f7`, bars `#eaecf0`, lines `#d0d4db`, subtle lines `#e8eaee`, faint text `#717884`. The dark theme stays as it is.
2. **Status bar, option 2a:** it starts with the server's color square and "server · database". No colored line.
3. **"No query open":** a hint, a `New query` button and three shortcuts. The button opens the query on the database clicked last in the tree, else on the first connected server's default database.
4. **A failed statement gets an `Error` tab** in the result strip, with the full message, the statement number and line, and `Copy message`. Results of earlier statements stay in their tabs next to it.

### Decided by the planner (small and reversible; reported to the owner)

5. **`--hover` in the light theme becomes `#dfe3e9`** (was `#eef1f5`). The old value is lighter than the new bars, so hovering a tab or toolbar button would have lit it up instead of darkening it.
6. **"Results from server · database" leaves the status bar** while the results match the tab's target: the new first item says the same. The warning for results from somewhere else ("Results are from … Run to refresh.") stays.
7. **The `Error` tab opens by itself** when a run fails. Clicking a result tab leaves it; the next failed run opens it again.
8. **Without a database to open on** (the first server has no default database and its list isn't loaded yet), `New query` is disabled and says why.
9. **While a run has produced nothing yet,** the result pane shows the status bar's running text ("Executing statement 2 of 3...") with a spinner, not "No results yet".
10. **A cancelled run with no rows** says "Query cancelled".
11. **"1 record affected"** in the singular, in the pane and the status bar (today "1 records affected").
12. **`Copy message` says "Copied" for two seconds** after a click; the app has no other copy confirmation to follow.
13. **Account page section titles are 16 px** (were 14 px, the same as the field labels).

### What we found in the code

- Light tokens: `--surface #f8f9fb`, `--chrome #f3f4f6`, `--line #d9dce1`, all within 5 % of white.
- `DatabaseCommandStatusBar` gets `resultsFrom` from `DatabaseCommandAndResult`, which has the tab's `target` (`serverName`, `databaseName`, `color`).
- `MainBar` renders nothing while there are no tabs. A new tab comes from `useCommandQueryContext().queryForDatabase(connectionId, databaseName, schema)`.
- The tree keeps its selection inside `ui/treeView`; nothing outside knows the clicked node. `useContextMenuHandlers.handleOnNodeClick` sees every click. `getNodeHierarchy(node)` gives the node's database and server nodes (the server node's `id` is the connection id), and `null` for a server node or the Databases folder.
- `DatabaseCommandResultView` returns `null` without result sets (or a small "N records affected"). A failed run's message is only in the status bar, cut off with a tooltip.
- The server writes a script's error as `Statement 2 of 3 (line 2): <message>` (`ExecuteQueryHandler.AtStatement`); a single statement's error has no prefix.
- `react-icons/lu` (installed) has `LuSquareTerminal`, `LuTable2`, `LuCircleCheck`, `LuCircleAlert`, `LuBan`, `LuPlus`.

### 5.2 `runStatus.ts` (additions, all pure)

```ts
// "1 record affected", "1,234 records affected".
export function recordsAffectedText(count: number): string;

// The id of the Error tab in a result strip; result sets have their own ids.
export const ERROR_TAB_ID = 'error';

// Which tab of the result strip shows. picked: the tab the user clicked last (null: none yet).
// A failed run opens its Error tab by itself: its result sets are new, so a tab picked in an earlier run no
// longer exists. Without an error, a tab that is gone falls back to the first result. null: nothing to show.
export function activeResultTabId(resultSetIds: string[], picked: string | null, hasError: boolean): string | null;

export interface RunError {
  // null for a single statement, or an error that is not about a statement (a lost connection).
  statement: { number: number; count: number; line: number } | null;
  message: string;
}

// Splits the server's "Statement 2 of 3 (line 2): <message>" (ExecuteQueryHandler.AtStatement) into its parts.
export function parseRunError(error: string): RunError;

// What happened to the other statements of a script whose statement `number` (from 1) failed.
export function statementsAroundFailure(number: number, count: number): string;
```

- `recordsAffectedText`: `count.toLocaleString('en-US')`, then ` record affected` for 1, else ` records affected`.
- `activeResultTabId`, in this order: `picked === ERROR_TAB_ID && hasError` → `ERROR_TAB_ID`; `picked` is in `resultSetIds` → `picked`; `hasError` → `ERROR_TAB_ID`; else `resultSetIds[0] ?? null`.
- `parseRunError`: the pattern `/^Statement (\d+) of (\d+) \(line (\d+)\): ([\s\S]*)$/`. No match: `{ statement: null, message: error }`.
- `statementsAroundFailure`: two sentences joined by a space, each left out when it has nothing to say.
  - Before (`number - 1` statements): 1 → `Statement 1 ran.`; more → `Statements 1 to {number - 1} ran.`
  - After (`count - number` statements): 1 → `Statement {count} was not run.`; more → `Statements {number + 1} to {count} were not run.`

`runStatus.test.ts` adds:

| Call | Expected |
|---|---|
| `recordsAffectedText(1)` | `1 record affected` |
| `recordsAffectedText(0)`, `(1234)` | `0 records affected`, `1,234 records affected` |
| `activeResultTabId(['a','b'], null, false)` | `'a'` |
| `activeResultTabId(['a','b'], 'b', false)` | `'b'` |
| `activeResultTabId(['a','b'], 'gone', false)` | `'a'` |
| `activeResultTabId(['a','b'], 'gone', true)` | `'error'` |
| `activeResultTabId(['a','b'], 'a', true)` | `'a'` |
| `activeResultTabId(['a'], 'error', true)` | `'error'` |
| `activeResultTabId(['a'], 'error', false)` | `'a'` |
| `activeResultTabId([], null, true)`, `([], null, false)` | `'error'`, `null` |
| `parseRunError('Statement 2 of 3 (line 2): 42P01: relation "x" does not exist')` | `{ statement: { number: 2, count: 3, line: 2 }, message: '42P01: relation "x" does not exist' }` |
| `parseRunError('Statement 1 of 2 (line 1): first\nsecond')` | message `'first\nsecond'` |

### 5.3 `queryTargets.ts` (addition, pure)

```ts
export interface TreeDatabase {
  connectionId: string;
  databaseName: string;
}

export interface NewQueryTarget extends TreeDatabase {
  serverName: string;
  color: string;
}

// Where the "New query" button of the empty workspace opens its tab: the database clicked last in the tree while
// its server is still connected, else the first connected server's default database, else that server's first
// database. null: nothing to open on yet (no server, or its database list hasn't arrived).
export function newQueryTarget(
  last: TreeDatabase | null,
  connections: DatabaseServerConnection[],
  schemas: DatabaseSchema[] | null,
): NewQueryTarget | null;
```

- A connection counts as connected when its `connectedResult` is set. `serverName` is the connection's `name`, `color` its `color`.
- `last` with a connected connection (`findConnection`) → that connection and `last.databaseName`.
- Else the first connected connection `c`: its `connectedResult.databaseName` when not empty; else, when `databaseList(schema of c)` is `loaded` with at least one name, the first name; else `null`.

`queryTargets.test.ts` (new; build whole `DatabaseServerConnection` and `DatabaseSchema` objects with a small helper in the test file, no casts): the last clicked database wins; a last clicked database whose server is gone falls back to the first server; the first server's default database; no default → the first loaded database; no default and no list → `null`; no connections → `null`.

## 6. Edge cases & don'ts

- **Don't touch `:root.dark`,** and don't add tokens.
- **Result sets stay mounted** while the Error tab shows (hidden, as inactive results are today): they keep their filter, sort and column widths.
- **The Error tab has no grid selection:** the status bar's "rows × columns selected" must not show a hidden result's selection.
- **Don't change the status bar's failure text** ("Query execution failed", "Error: …"): the Error tab adds to it.
- **Don't parse the error anywhere but `parseRunError`,** and don't change the server's text.
- **An error that is not from a statement** (a lost connection, `CONNECTION_LOST_MESSAGE`) shows as "The query failed" with its message, no statement line.
- **The reducer must return the same state for an unchanged tree click** (5.12).
