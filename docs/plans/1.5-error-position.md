# 1.5 Error position

## 1. Goal

When a statement fails, show where: the place PostgreSQL reports is marked in the editor, and the Error tab names the line and column, shows that line, and jumps to it. Errors raised inside a function also show PostgreSQL's `QUERY` and `CONTEXT` lines.

Roadmap: Phase 1 "Later", "Error panel and error position", numbered **1.5** by this step. The panel half of that row already exists: it is the Error tab of step 1.4c. Docs it changes: `README.md` ("Features"), `docs/api.md` ("Streaming query results"), `mdb-navigator-ui/README.md` ("How a query runs in the UI"), `docs/ROADMAP.md`.

## 2. Decisions

The owner chose this step on 2026-11-24. The choices below are the planner's, listed for the owner; none was discussed.

1. **The server sends one number, `errorOffset`,** in `CommandFinished`: the index of the reported place in the script the browser sent, counted in UTF-16 code units. .NET and JavaScript strings both count that way, so the UI uses it on its own copy of the text as it is. The error text and its `Statement 2 of 5 (line 14):` prefix don't change.
2. **The provider does the arithmetic.** PostgreSQL gives a 1-based position in characters of the one statement it received. Turning that into a place in the script needs three things only the provider knows: where the statement starts in the script, what it put in front (`EXPLAIN (...)`), and that PostgreSQL counts an emoji as one character where a string counts two. Checked against PostgreSQL 17 on 2026-11-24 (see "What we found").
3. **The mark in the editor is our own decoration,** not a Monaco marker: a soft red box with a solid underline, a red bar in the gutter, a tick in the scrollbar, and the message's first line on hover. The editor's own syntax check (monaco-sql-languages) draws a wavy line, so the two can be told apart: one is what the editor guesses, the other what the database said.
4. **The mark stays until the tab's next run.** It moves with the text while the user types, so "Go to error" still lands on it. It is not cleared on the first edit.
5. **Nothing moves by itself.** A failed run doesn't scroll the editor, move the caret or take the focus: the user may be typing somewhere else. The Error tab, which already opens by itself, gets a **Go to error** button.
6. **Text edited while the query ran gets no mark.** The offsets no longer mean the same text. The Error tab still shows the line and column of the text as it was run, and Go to error says why it can't jump.
7. **What is marked:** the word at the reported place (a dotted name whole: `pg_temp.zz`), a quoted name or string up to its closing quote, otherwise one character. For "syntax error at end of input" the place is after the text, so the last word before it is marked.
8. **The Error tab shows the failing line,** cut to about 120 characters around the place when the line is longer (a one-line `INSERT` can be megabytes).
9. **`QUERY` and `CONTEXT` lines** are added to every database error message, after `DETAIL` and `HINT`, in psql's order. That includes the errors the REST endpoints return (shown as toasts); those rarely have either line.
10. **Run still runs the whole editor.** Only Explain works on a selection (step 2.1); its error place is mapped back through the selection's start.
11. **Not in this step:** the Messages panel (notices, rows affected and timing per statement), and marking a place for errors inside a function (`InternalPosition` points into the function's own query, not the user's text).

### What we found

- `ResultError.tsx` (the Error tab) shows the heading, the statement's first line, the full message and `Copy message`. `parseRunError` in `runStatus.ts` splits the server's prefix.
- `QueryExecution.RunAsync` keeps the running statement in `current` (`StatementStarted`) and builds the message with `_errorDescriber.Describe(ex)`.
- `ScriptStatement.Text` is a piece of the script that starts at the splitter's `textStart`, leading comments included, so `script.Substring(textStart, Text.Length) == Text`.
- `PostgresExplain.Build` sends `"EXPLAIN (…)\n" + statement.Text`.
- Npgsql 10.0.3: `PostgresException.Position` (0 when not given), `InternalQuery`, `Where`. Its public constructor takes them: `(messageText, severity, invariantSeverity, sqlState, detail, hint, position, internalPosition, internalQuery, where, …)`.
- Measured against PostgreSQL 17 through `NpgsqlBatch`:

  | Statement | `Position` | Note |
  |---|---|---|
  | `select * from no_such_table` | 15 | the name's first character |
  | `select '😀' from no_such_table` | 17 | the emoji counts as one |

`PostgresErrorDescriber.OffsetInScript` (add `using MDBNavigator.Providers.Abstractions.Queries;`):
```csharp
public int? OffsetInScript(Exception exception, string script, StatementStarted statement)
{
    // Position: 1-based, in characters of the text that was sent; 0 when PostgreSQL gave none. InternalPosition
    // (a query run inside a function) is not a place in the user's text: the QUERY and CONTEXT lines cover it.
    if (exception is not PostgresException { Position: > 0 } pg)
    {
        return null;
    }

    // Characters into the statement's own text. Below 0: the place is in what the provider put in front.
    var characters = pg.Position - 1 - statement.PrefixLength;
    if (characters < 0 || statement.Offset < 0 || statement.Offset > script.Length)
    {
        return null;
    }

    // PostgreSQL counts characters; a string counts UTF-16 units, where an emoji is two.
    var index = statement.Offset;
    for (; characters > 0 && index < script.Length; characters--)
    {
        index += char.IsSurrogatePair(script, index) ? 2 : 1;
    }

    // index == script.Length is a real answer: "syntax error at end of input" points one past the last character.
    return characters == 0 ? index : null;
}
```

### 5.6 `features/databaseCommand/errorLocation.ts` (pure, tested)

```ts
import { RunSource } from '../../models/databaseCommand/query/runSource';

// The failing line is shown whole up to this many characters; a longer one is cut around the error.
export const EXCERPT_MAX = 120;
// How much of a cut line is kept in front of the error.
export const EXCERPT_LEAD = 40;

// Indexes into the run's text; end is exclusive.
export interface ErrorSpan { start: number; end: number }

export interface ErrorExcerpt { before: string; marked: string; after: string }

export interface ErrorLocation {
  // In the editor, 1-based, as Monaco counts (a column is one UTF-16 unit).
  line: number;
  column: number;
  // What to mark, in the run's text.
  span: ErrorSpan;
  // The line the error is on, for the Error tab.
  excerpt: ErrorExcerpt;
}

export function offsetToPosition(text: string, offset: number): { line: number; column: number };
export function errorSpan(text: string, offset: number): ErrorSpan;
export function errorExcerpt(text: string, span: ErrorSpan): ErrorExcerpt;
export function locateError(source: RunSource, offset: number): ErrorLocation;
// For a Monaco hover, which reads its text as Markdown.
export function escapeMarkdown(text: string): string;
```

In all of them, `o` is `offset` clamped to `0..text.length`.

**`offsetToPosition`:** 1-based line and column of `o`.
- Walk `i` from 0 to `o - 1`. `\n` starts a new line. `\r` starts a new line only when the next character is not `\n` (so `\r\n` counts once, at its `\n`).
- The column is `o - lineStart + 1`.
- Cases:
  - `('select 1', 0)` → 1, 1
  - `('select 1', 7)` → 1, 8
  - `('a\nbc', 1)` → 1, 2
  - `('a\nbc', 2)` → 2, 1
  - `('a\nbc', 4)` → 2, 3
  - `('a\r\nbc', 3)` → 2, 1
  - `('a\rb', 2)` → 2, 1
  - `('ab', 99)` → 1, 3
  - `('ab', -5)` → 1, 1

**`errorSpan`:** a word character is `/[A-Za-z0-9_$\u0080-\uFFFF]/` (the same set the server's splitter calls a word; it covers both halves of an emoji).
1. When `o < text.length` and `text[o]` is not white space:
   - **A word character:** the span runs to the end of the word. A `.` continues it when the character after the `.` is a word character.
   - **`"` or `'`:** the span runs to the matching closing quote, inclusive. The same quote twice in a row (`""`, `''`) is inside it. It stops at the end of the line when the quote isn't closed there.
   - **Anything else:** one character.
2. Otherwise (white space, or the end of the text): find the last character before `o` that is not white space, at `p`.
   - A word character: the span is that whole word, from its first character to `p + 1`.
   - Anything else: `p` to `p + 1`.
   - No such character: `{ start: o, end: o }`.
- Cases:
  - `('select * from no_such_table where x', 14)` → 14, 27
  - `('select * from pg_temp.zz', 14)` → 14, 24
  - `("select 'abc'::int", 7)` → 7, 12
  - `('select "No Such" from t', 7)` → 7, 16
  - `('select "a""b" from t', 7)` → 7, 13
  - `("select 'abc", 7)` → 7, 11
  - `("select 'ab\ncd'", 7)` → 7, 10
  - `('where relname = 5', 14)` → 14, 15
  - `('select * from', 13)` → 9, 13
  - `('select * from\n;', 13)` → 9, 13
  - `('select * from;', 13)` → 13, 14
  - `('select (', 8)` → 7, 8
  - `('select 😀x', 7)` → 7, 10
  - `('', 0)` → 0, 0
  - `('   ', 3)` → 3, 3

**`errorExcerpt`:**
1. `lineStart` is the index after the last `\n` or `\r` before `span.start` (0 when there is none). `lineEnd` is the index of the first `\n` or `\r` at or after `span.start` (`text.length` when there is none).
2. When `lineEnd - lineStart <= EXCERPT_MAX`: `from = lineStart`, `to = lineEnd`.
3. Otherwise: `from = max(lineStart, span.start - EXCERPT_LEAD)`, `to = min(lineEnd, from + EXCERPT_MAX)`, and when that leaves fewer than `EXCERPT_MAX` characters, `from = max(lineStart, to - EXCERPT_MAX)`.
4. `markEnd = min(span.end, to)`.
5. `before` is `'…'` when `from > lineStart`, then `text.slice(from, span.start)`. `marked` is `text.slice(span.start, markEnd)`. `after` is `text.slice(markEnd, to)`, then `'…'` when `to < lineEnd`.
6. Every tab in the three parts becomes one space, so the line reads the same in the tab's monospace line.
- Cases:
  - A short line comes whole: `('select 1;\nselect * from nope', { start: 24, end: 28 })` → `{ before: 'select * from ', marked: 'nope', after: '' }`.
  - Text after the mark stays: `('select nope from t', { start: 7, end: 11 })` → `{ before: 'select ', marked: 'nope', after: ' from t' }`.
  - A 300-character line with the span at 200..204: `before` starts with `…` and is 41 characters long, `after` ends with `…`, and the three parts together are 122 characters.
  - The same line with the span at 2..6: no `…` in front, one at the end.
  - An empty span gives `marked: ''`.
  - A tab in `before` comes out as a space.

**`locateError`:** `p = offsetToPosition(source.text, offset)`, `span = errorSpan(source.text, offset)`.
- `line` is `source.line + p.line - 1`.
- `column` is `source.column + p.column - 1` when `p.line` is 1 (the first line of a selection starts in the middle of an editor line), otherwise `p.column`.
- `excerpt` is `errorExcerpt(source.text, span)`.
- Cases:
  - `({ text: 'select 1;\nselect * from nope', line: 1, column: 1 }, 24)` → line 2, column 15, span 24..28.
  - `({ text: 'select nope', line: 10, column: 5 }, 7)` → line 10, column 12.
  - `({ text: 'select\n  nope', line: 10, column: 5 }, 9)` → line 11, column 3.

**`escapeMarkdown`:** `text.replace(/[\\`*_{}[\]()#+\-.!|<>~]/g, '\\$&')`. Cases: `'a_b'` → `'a\\_b'`; `'*x*'` → `'\\*x\\*'`; `'plain'` unchanged.

## 6. Edge cases & don'ts

- **Don't parse the place out of the message,** and don't compute it in the UI from PostgreSQL's number. The UI only ever sees `errorOffset`.
- **Don't change the error text's format** or `AtStatement`. `parseRunError` and the status bar depend on it, and the existing API tests assert it.
- **Don't wrap or replace the exception** in the provider to carry the place. `QueryExecution` filters on `DbException`, and `Classify` reads the SQLSTATE of the original.
- **Don't add the offset to `StatementStartedDto`** or any hub message other than `CommandFinished`.
- **No PostgreSQL knowledge in Workbench.Core:** it passes the exception, the script and the statement to the describer and stores the answer. `Position`, code points and the `EXPLAIN` prefix stay in the provider.
- **Don't use `monaco.editor.setModelMarkers`.** The language service owns markers, and they don't follow edits in a way we can read back. The decoration collection does.
- **Don't clear the mark in `handleEditorChange`,** and don't move the caret, scroll or focus when a run fails.
- **Don't change Run** to run the selection.
- **No new npm or NuGet packages.** The architecture tests pass unchanged: no project or reference is added.
- **`JsonCellValue.cs` ↔ `cellValue.ts` and the other synced pairs are untouched.**
- **A place at the very end of the text** (`errorOffset === text.length`) is valid everywhere: `offsetToPosition` gives the column after the last character, `errorSpan` marks the last word.
- **A surrogate pair cut in half by the excerpt's window** shows as one odd character at the cut. Accepted; don't add code for it.
- **Line endings:** the sent text is what Monaco's model gave (`getValue`, `getValueInRange`), so offsets match the model whether it uses `\n` or `\r\n`. A query opened with `executeImmediately` whose text has mixed line endings fails the equality check and gets no mark. Accepted.
- **The demo:** nothing demo-specific. `QUERY` and `CONTEXT` show what psql shows any user.
- **Lint:** zero warnings, no `any`. The effect's dependency list is exactly `[editorMounted, source, errorOffset, error]`.
- **Release build:** warnings are errors; `required` on `StatementStarted.Offset` makes a forgotten construction site a compile error, which is intended.
