# 0.7b API smoke tests

## 1. Goal

A test project that drives the whole API over HTTP and SignalR, against a throwaway PostgreSQL: sign in, connect, load the tree, generate scripts, run and cancel queries, saved connections, account deletion. The tests know nothing about the projects behind the API, so they keep passing unchanged while 0.7c–0.7g move the code, and that is what proves the moves changed nothing.

Roadmap step **0.7b** ([ROADMAP.md](../ROADMAP.md), "0.7 Modular structure"); it is also the first part of 0.3c.

Docs it changes: `README.md` ("Repository layout" and "Development") and the owner's local `CLAUDE.md` ("Building and checking").

**No application code changes in this step.** Only the new test project, the solution file, the package list and the docs.

## 2. Decisions

- **Through the front door only.** The tests use `WebApplicationFactory<Program>` (the real `Program.cs`, in memory) and assert on HTTP status codes, JSON and hub messages. No handler, service or `DbContext` is touched from a test. The one exception is a read of the temporary SQLite file in the account-deletion test, by table name, because no endpoint can show that a deleted user's rows are gone.
- **PostgreSQL comes from Testcontainers** (`Testcontainers.PostgreSql`, MIT): `dotnet test` starts a `postgres:17-alpine` container and removes it afterwards. Docker has to be running. This keeps the owner's PostgreSQL out of the tests entirely, and works the same in CI (0.4c).
- **The app database is a temporary SQLite file**, set with `UseSetting("ConnectionStrings:AppDb", ...)`. The fixture checks that the file exists before any test runs, so a failed override can never send tests to `src/MDBNavigator.API/data`.
- **Environment `Testing`**, not `Development`: the owner's user secrets and `appsettings.Development.json` are then not loaded, so the tests see the defaults of `appsettings.json` plus the fixture's own settings.
- **Cookies are handled by hand.** Outside Development the session cookie is `Secure`, and the SignalR client needs it too, so a signed-in session keeps the `Cookie` header itself and sends it on both.
- **SignalR over long polling**, through the test server's own handler. WebSockets would need a real port.
- **One app and one container for all tests** (an xUnit collection fixture), and **a fresh account per test** where state matters, so tests don't depend on their order and never hit each other's limits.
- **Project name `MDBNavigator.API.Tests`**, matching `MDBNavigator.API`. It stays under that name through 0.7c–0.7g.
- **xUnit 2.9.3**, as in the existing test project.

All of this was tried in a scratch project first: the override, the cookie, the hub over long polling and the container work as written below.

### `ApiFactory`

```csharp
public sealed class ApiFactory : WebApplicationFactory<Program>
{
    public const string AdminEmail = "admin@example.test";
    public const string AdminPassword = "correct-horse-battery";

    public string AppDbPath { get; } = Path.Combine(Path.GetTempPath(), $"mdbnav-tests-{Guid.NewGuid():N}.db");

    protected override void ConfigureWebHost(IWebHostBuilder builder)
    {
        // Not Development: the owner's user secrets and appsettings.Development.json stay out of the tests.
        builder.UseEnvironment("Testing");

        // UseSetting, not ConfigureAppConfiguration: Program.cs reads its options while it builds the host, and only
        // UseSetting values are there that early.
        builder.UseSetting("ConnectionStrings:AppDb", $"Data Source={AppDbPath}");
        builder.UseSetting("Auth:Mode", "Accounts");
        builder.UseSetting("Auth:SignUp", "Open");
        builder.UseSetting("Auth:Admin:Email", AdminEmail);
        builder.UseSetting("Auth:Admin:Password", AdminPassword);
        builder.UseSetting("Email:Delivery", "None");
        builder.UseSetting("Captcha:Provider", "None");
        // The container is on localhost, which the default guard (Public, with open sign-up) refuses.
        builder.UseSetting("ConnectionGuard:Mode", "Off");
        builder.UseSetting("SavedConnections:PasswordKey", Convert.ToBase64String(RandomNumberGenerator.GetBytes(32)));
        // The whole suite comes from one address within a minute.
        builder.UseSetting("RateLimiting:AuthRequestsPerMinute", "10000");
        builder.UseSetting("RateLimiting:ConnectsPerMinute", "10000");
        builder.UseSetting("RateLimiting:QueriesPerMinute", "10000");
    }
}
```

`MaxRunningQueriesPerUser` (3) and `FailedConnectsBeforeWait` (5) keep their defaults: one test relies on the first.

### `AppFixture` and the collection

```csharp
[CollectionDefinition(Name)]
public sealed class ApiCollection : ICollectionFixture<AppFixture>
{
    public const string Name = "API";
}

public sealed class AppFixture : IAsyncLifetime
{
    public const string Database = "postgres";
    public const string PgUser = "postgres";
    public const string PgPassword = "postgres";

    public ApiFactory Factory { get; }
    public string PgHost { get; }
    public int PgPort { get; }

    public Task InitializeAsync();   // start the container, run SampleSchema, create the factory, start the app, check AppDbPath exists
    public Task DisposeAsync();      // dispose the factory, SqliteConnection.ClearAllPools(), delete AppDbPath (+ "-wal", "-shm"), dispose the container

    public HttpClient CreateAnonymousClient();          // no cookie, no id header
    public Task<ApiSession> SignInAsync(string email, string password);
    public Task<ApiSession> SignInAsAdminAsync();
    public Task<(ApiSession Session, string Email, string Password)> NewUserAsync();   // registers "user-{guid}@example.test" with password "smoke-test-password", then signs in
    public object ConnectBody(string? password = PgPassword, string serverType = "PostgreSQL", Guid? savedConnectionId = null);
}
```

- Container: `new PostgreSqlBuilder("postgres:17-alpine").WithUsername(PgUser).WithPassword(PgPassword).WithDatabase(Database).Build()`. `PgHost` is `container.Hostname`, `PgPort` is `container.GetMappedPublicPort(5432)`.
- Every client: `Factory.CreateClient(new WebApplicationFactoryClientOptions { BaseAddress = new Uri("https://localhost"), HandleCookies = false })`.
- The sample schema is created with `container.ExecScriptAsync(SampleSchema)`; fail the fixture if its exit code is not 0. `SampleSchema`:

```sql
create table smoke_items (id int primary key, name varchar(50) not null, note text);
insert into smoke_items values (1, 'one', null), (2, 'two', 'x');
create view smoke_items_view as select id, name from smoke_items;
create function smoke_add(a int, b int) returns int language sql as 'select a + b';
create procedure smoke_noop() language sql as 'select 1';
```

- `ConnectBody` returns `new { serverType, serverName = PgHost, port = PgPort, userName = PgUser, password, databaseName = Database, savedConnectionId }`.

### `ApiSession`

One signed-in browser tab.

```csharp
public sealed class ApiSession : IDisposable
{
    public HttpClient Client { get; }     // sends "Cookie" and "id" on every request
    public string TabId { get; }          // a new GUID per session
    public string Cookie { get; }         // "mdbnav_session=..." taken from the login response's Set-Cookie headers

    public ApiSession WithNewTab();                               // same cookie, another tab id
    public Task<string> ConnectAsync();                           // POST connect with fixture.ConnectBody(), asserts 200, returns connectionId
    public Task<HubListener> ListenAsync();                       // connected hub for this tab
    public Task<QueryRun> RunAsync(string connectionId, string sql, HubListener hub);   // POST api/databaseCommand, asserts 202, waits for CommandFinished (30 s)
}

public sealed record QueryRun(string ExecutionId, IReadOnlyList<JsonElement> Statements, IReadOnlyList<JsonElement> Batches, JsonElement Finished);
```

- Sign-in: `POST /api/auth/login?useCookies=true` with `{ email, password }`; the cookie header is every `Set-Cookie` value up to its first `;`, joined with `"; "`.
- Execute body: `{ connectionId, databaseName = "postgres", cmdQuery = sql, executionId = Guid.NewGuid().ToString() }`.

### `HubListener`

```csharp
public sealed class HubListener : IAsyncDisposable
{
    public static Task<HubListener> StartAsync(ApiFactory factory, string tabId, string cookie);

    public Task<JsonElement> WaitForStatementStartedAsync(string executionId, TimeSpan timeout);
    public Task<JsonElement> WaitForFinishedAsync(string executionId, TimeSpan timeout);
    public IReadOnlyList<JsonElement> Statements(string executionId);
    public IReadOnlyList<JsonElement> Batches(string executionId);
}
```

Built as in the trial:

```csharp
new HubConnectionBuilder()
    .WithUrl($"https://localhost/batchCommandResult?tabId={tabId}", options =>
    {
        options.HttpMessageHandlerFactory = _ => factory.Server.CreateHandler();
        options.Transports = HttpTransportType.LongPolling;
        options.Headers.Add("Cookie", cookie);
    })
    .Build();
```

It subscribes to `StatementStarted`, `BatchCommandResult` and `CommandFinished` as `JsonElement`, and files each message under its `executionId` property. Messages arrive on another thread: use concurrent collections and `TaskCompletionSource` with `RunContinuationsAsynchronously`. A wait that times out fails the test with a message naming the execution and the event.

### Message and response shapes the tests rely on

JSON is camelCase. Hub enum values are strings.

| What | Shape |
|---|---|
| Error body | `{ statusCode, message, details? }` |
| `GET /api/auth/settings` | `{ mode, signUp, providers, emailEnabled, captchaProvider, turnstileSiteKey, rememberPasswords }` |
| `GET /api/auth/me` | `{ email, isAdmin, signInMethod }` |
| Connect | `{ connectionId, connectionName, serverName, port, serverType, userName, databaseName, savedConnectionId }` |
| Execute | `202` with `{ id }` equal to the execution id |
| `StatementStarted` | `{ executionId, statementIndex, statementCount, line }` |
| `BatchCommandResult` | `{ id, executionId, index, resultSetIndex, isFirstBatch, isLastBatch, fields: [{ index, fieldName, category, dataTypeName }] (first batch only), rows: [[...]], truncated, skippingRest }` |
| `CommandFinished` | `{ executionId, status: "Completed" \| "Failed" \| "Cancelled", rowCount, recordsAffected, elapsedMs, truncated, error }` |
| Saved connection | `{ id, name, serverType, serverName, port, databaseName, userName, color, hasPassword }` |
| Saved connection request | `{ name, serverType, serverName, port, databaseName, userName, color, rememberPassword, password }` |

## 6. Edge cases & don'ts

- **Don't change anything under `src/`.** If a test can't be written without an application change, stop and ask.
- **When the app behaves differently from a row above:** the app is the reference, not this plan. If the README documents the behavior, or it is plainly intended, adjust the expectation and list the difference in the summary. If it looks like a bug, leave that one fact out, don't assert the bug, and report it. Never weaken a test to "status is not 500".
- **Never connect the tests to the owner's PostgreSQL** (the `PostgreSQLDB` container on port 5432, or anything from `mdb-navigator-ui/.env.development.local`). Only the Testcontainers instance.
- **Never let the app under test open `src/MDBNavigator.API/data/mdbnavigator.db`.** The fixture's check that `AppDbPath` exists after startup must stay, and must run before the first test.
- **No fixed ports, no `Thread.Sleep`.** Wait on hub messages with a timeout.
- **Unique names** for anything a test creates in PostgreSQL or as a saved connection where another test could collide (`Guid.NewGuid():N`). The sample objects are read-only for the tests.
- **Cancel what a test starts.** The cap test leaves three sleeping queries unless it cancels them; they would count against nothing else (fresh user), but they hold connections for 30 s.
- **Dispose** every `HubListener` and `ApiSession` (`await using` / `using`).
- **Don't add packages** beyond the three listed. No assertion library (FluentAssertions 8+ is commercial); plain xUnit asserts.
- **Email addresses in tests are fake** (`@example.test`). Nothing is logged by the tests.
- **Logout does not invalidate a cookie that the client keeps** (the session is the cookie itself); that is why there is no "signed out, then refused" test.
- **Build like the repository does:** a Release build treats warnings as errors, so the test project must be warning-free (nullable included).
