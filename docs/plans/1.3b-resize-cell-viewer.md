# 1.3b Result grid: resize, column virtualization, cell viewer

## 1. Goal

A column's width can be changed by dragging the edge of its header, or fitted to its content with a double-click. Only the visible columns are rendered, so very wide results stay responsive. Double-clicking a cell (or pressing Enter) opens its full value in a dialog, with JSON formatted for reading.

Roadmap step 1.3b (`docs/ROADMAP.md`), built on the branch `1.3-result-grid` after 1.3a. UI only. Changes these docs: root `README.md` ("Features"), `mdb-navigator-ui/README.md` (the last paragraph of "How a query runs in the UI"). Mock: https://claude.ai/artifact/8YCZfS9K3puEqj7Gigjg5e (boards "1.3b Resize a column" and "1.3b Cell viewer").

**Before starting:** 1.3a must be in the working tree: `mdb-navigator-ui/src/ui/dataGrid/selection.ts` exists and `npm test` passes in `mdb-navigator-ui`. Otherwise stop and ask. Read `docs/plans/1.3a-select-copy.md` section 5 first: this step builds on those contracts and must not change them.

## 2. Decisions

Agreed with the owner on 2026-11-13:

1. **Resize by dragging a header edge; the column follows the pointer.** Double-click the edge to fit the content.
2. **The cell viewer is a dialog**, opened by a double-click on a cell, by Enter on the active cell, or from the right-click menu. A side panel that follows the selection may come later.
3. **Column virtualization goes in here**, because resizing touches the same code.

Decided by the planner (small, reversible):

- **Widths are kept for the life of one result set.** A new run measures again.
- **A dragged column may be 40 to 2,000 px wide.** Fitting and the first automatic measuring keep the existing limits (60 to 1,000 px).
- **JSON is formatted without being parsed into numbers**, so a large number such as `12345678901234567890` is shown exactly as stored. "Copy value" copies the original text, not the formatted one.
- **The viewer has a "Wrap long lines" checkbox**, off at first.
- **The viewer's title** is `column · type · row N`, with the database's type name and the row's number in the result.

### What we found in the code

- `ui/modalWindow/ModalWindow.tsx` passes `onCloseModal` to its child with `cloneElement`, so the child must be a component (a plain `<div>` would get an unknown prop). It closes on its X and on an outside click, but not on Esc, and it does not move the focus. The viewer adds both.
- `ui/sidebar/HorisontalSidebar.tsx` shows the drag pattern to copy: pointer capture, `startDrag`/`endDrag` from `dragSelection.ts`, and a cleanup on unmount.
- `@tanstack/react-virtual` caches column sizes. After widths change, `measure()` must be called, or the visible-column range is computed from the old sizes.

## 5. Contracts

### 5.1 `columnWidths.ts`

Move `createTextMeasurer`, `clampWidth`, `headerWidths` and `computeColumnWidths` here from `DataGrid.tsx`, with their constants (`CELL_PADDING`, `MIN_COLUMN_WIDTH`, `MAX_COLUMN_WIDTH`, `WIDTH_SAMPLE_ROWS`, `FONT_SIZE`, `HEADER_FONT_WEIGHT`) and comments, unchanged in behavior. Export `headerWidths`, `computeColumnWidths` and:

```ts
export const MIN_RESIZE_WIDTH = 40;
export const MAX_RESIZE_WIDTH = 2000;

// The width that fits one column's header and its first displayed rows (a double-click on the header edge).
export function fitColumnWidth(
  column: DataGridColumn,
  columnIndex: number,
  getRow: (index: number) => CellValue[],
  rowCount: number,
): number
```

`fitColumnWidth` measures the header (sans, semibold) and the first `min(rowCount, WIDTH_SAMPLE_ROWS)` displayed rows of that column (mono, `formatCell(...).text`), and returns the largest through `clampWidth`. `DataGridColumn` is imported as a type from `DataGrid.tsx` (`import type`, so the two files can refer to each other). These functions need a canvas, so they get no unit test.

### 5.2 `cellViewerText.ts`

```ts
export interface ViewerText {
  text: string;
  // True when the text was laid out for reading and differs from the stored value.
  formatted: boolean;
}

// What the cell viewer shows for a value. JSON is indented; everything else is the value's full text.
export function viewerText(value: CellValue | undefined, category: DbTypeCategory): ViewerText

// Re-indents JSON text by two spaces without parsing its values, so numbers keep every digit.
// The caller makes sure the text is valid JSON.
export function prettyJsonText(json: string): string
```

`viewerText`:

- `null`/`undefined` → `{ text: '', formatted: false }` (the viewer shows NULL itself).
- Category `Json` and a string value: if `JSON.parse(value)` succeeds (in a `try`), `{ text: prettyJsonText(value), formatted: true }`; otherwise the raw string, `formatted: false`.
- An array or object value (PostgreSQL arrays, hstore): `{ text: JSON.stringify(value, null, 2), formatted: true }`.
- Anything else: `{ text: cellToText(value), formatted: false }`.

`prettyJsonText` walks the characters once, tracking whether it is inside a string (and whether the previous character was a backslash):

- Inside a string every character is copied as it is.
- Outside a string, whitespace is dropped.
- `{` or `[`: copy it; if the next non-whitespace character closes it (`}` or `]`), copy that too with nothing between (`{}`, `[]`); otherwise go one level deeper and start a new indented line.
- `}` or `]`: go one level up, start a new indented line, copy it.
- `,`: copy it and start a new indented line.
- `:`: copy it followed by one space.
- Everything else (numbers, `true`, `false`, `null`): copied as it is.

`cellViewerText.test.ts`: `prettyJsonText` on a nested object with an array (compare with the exact expected string); empty `{}` and `[]` stay on one line; a string containing `{`, `,`, `:` and an escaped quote is untouched; `12345678901234567890` and `1.10` keep every digit; already indented input gives the same output as compact input. `viewerText`: NULL; a `Json` string; a `Json` string that is not valid JSON (raw, not formatted); a `Text` string that looks like JSON (raw, not formatted, because only `category` decides); an array value; a number.

### 5.3 `CellViewer.tsx`

```tsx

  typeName: string;
```

- `CellViewerBody`:
  - `const shown = viewerText(value, category)`, `isNull = value === null || value === undefined`, state `wrap` (false).
  - Root: `<div className="flex w-[min(720px,calc(100vw-4rem))] flex-col">`.
  - The value: `<pre ref={valueRef} tabIndex={0} className="max-h-[60vh] min-h-24 overflow-auto border-y border-line bg-surface px-4 py-3 font-mono text-[13px] leading-5 outline-none …">`, plus `whitespace-pre-wrap break-words` when `wrap`, else `whitespace-pre`. For NULL it holds `<span className="italic text-fg-muted">NULL</span>`.
  - Footer: `<div className="flex items-center justify-between gap-4 px-4 py-3">`. Left: a `<label className="flex items-center gap-2 text-xs text-fg-muted">` with a checkbox and "Wrap long lines", and, when `shown.formatted`, `<span className="text-xs text-fg-muted">Formatted for reading. ### 5.5 `DataGrid.tsx`

Props are unchanged. Everything from 1.3a (selection, keyboard, menu, copy, ARIA) keeps working.

**Widths.** State stays `columnWidths: number[] | null`, filled once when the first rows arrive (now through `computeColumnWidths` from `columnWidths.ts`). `widths = columnWidths ?? headerWidths(columns)` as before.

**Column virtualization.** A second virtualizer finds the visible columns:

```ts
const columnVirtualizer = useVirtualizer({
  horizontal: true,
  count: columns.length,
  getScrollElement: () => scrollRef.current,
  estimateSize: index => widths[index],
  // The row-number column comes first, so the data columns start after it.
  paddingStart: rowNumberWidth,
  overscan: 3,
});
const visibleColumns = columnVirtualizer.getVirtualItems().map(item => item.index);

// The virtualizer caches sizes; without this it would keep computing the visible columns from the old widths.
useLayoutEffect(() => {
  columnVirtualizer.measure();
}, [columnVirtualizer, columnWidths, rowNumberWidth]);
```

Positions always come from `offsets` (`columnOffsets(widths, rowNumberWidth)`, 1.3a) and `widths`, never from the virtual items' `start`/`size`: `offsets` is right in the same render in which a width changes, and the virtualizer catches up one render later.

**Layout.** The CSS grid template goes away (`gridTemplateColumns` is deleted). Cells are placed absolutely:

- Content wrapper: `<div className="relative min-w-full" style={{ width: totalWidth }}>`.
- Header: `<div role="row" className="sticky top-0 z-10 h-7 border-b border-line bg-chrome font-sans font-semibold" style={{ width: totalWidth }}>` with `position: relative` coming from `sticky` (absolute children are placed against it).
  - Corner cell: `sticky left-0 z-[1] h-full border-r border-line bg-chrome`, `style={{ width: rowNumberWidth }}` (block level, so the absolute cells do not push it).
  - For each index in `visibleColumns`: the header cell, `absolute top-0 h-full truncate border-r border-line px-2 leading-7 cursor-pointer`, `style={{ left: offsets[c], width: widths[c] }}`, with the 1.3a selection tint and tooltip.
  - For each index in `visibleColumns`: a resize handle (below), rendered after all header cells so it sits on top.
- Rows container: `relative`, `style={{ height: virtualizer.getTotalSize() }}`, with the 1.3a delegated handlers.
- Each row: `absolute left-0 border-b border-line-subtle hover:bg-hover`, `style={{ width: totalWidth, height: ROW_HEIGHT, top: item.start }}` (width was `w-full`; it must be the content width so the sticky row number has room to stick). Keep `top`, as 1.3a left it: a `transform` would make each row its own stacking context and the selection outline would then paint over the sticky row numbers.
- The header is exactly `HEADER_HEIGHT` (28px) tall including its bottom border (`h-7` on the header row, `h-full` on its cells). In 1.3a it was 29px, one more than the constant; this layout fixes that.
  - Row-number cell: `sticky left-0 z-[1] h-full truncate border-r border-line px-2 text-right leading-6`, `style={{ width: rowNumberWidth }}`, with the 1.3a classes and `data-row`.
  - For each index in `visibleColumns`: the cell, `absolute top-0 h-full truncate border-r border-line-subtle px-2 leading-6`, `style={{ left: offsets[c], width: widths[c] }}`, with the 1.3a attributes and classes.
- `aria-colindex={c + 1}` on header cells and data cells, since not every column is in the DOM.

**Resizing.**

- State `resizing: number | null` (the column being dragged). A ref `resizeStart: { column: number; startX: number; startWidth: number } | null`.
- Handle, one per visible column: `<div role="separator" aria-orientation="vertical" aria-label={`Resize ${column.name}`} className="absolute top-0 z-[2] h-full w-[7px] cursor-col-resize touch-none" style={{ left: offsets[c] + widths[c] - 4 }} … />`, plus `bg-accent` while `resizing === c`.
  - `onPointerDown` (button 0): `preventDefault()`, `stopPropagation()` (a header click must not select the column), `setPointerCapture`, fill `resizeStart`, `setResizing(c)`, `startDrag('col')`.
  - `onPointerMove` while `resizeStart` is set: the new width is `startWidth + (e.clientX - startX)`, limited to `MIN_RESIZE_WIDTH`…`MAX_RESIZE_WIDTH` and rounded; `setColumnWidths` with a copy of `widths` in which that one column is replaced.
  - `onPointerUp` and `onLostPointerCapture`: clear `resizeStart`, `setResizing(null)`, `endDrag()`.
  - `onDoubleClick`: `stopPropagation()`; replace that column's width with `fitColumnWidth(columns[c], c, getRow, rowCount)`.
  - An unmount cleanup calls `endDrag()` if a drag is in progress, as in `HorisontalSidebar`.
- While `resizing !== null`, inside the content wrapper:
  - a guide line: `<div aria-hidden="true" className="pointer-events-none absolute top-0 z-20 h-full w-px bg-accent" style={{ left: offsets[resizing] + widths[resizing] - 1 }} />`;
  - a width label: `<div aria-hidden="true" className="pointer-events-none absolute z-20 whitespace-nowrap rounded bg-fg px-1.5 py-0.5 font-sans text-[11px] text-canvas" style={{ left: offsets[resizing] + widths[resizing] + 6, top: HEADER_HEIGHT + 4 }}>{columns[resizing].name}: {widths[resizing]} px</div>`. Both are placed against the content wrapper, so the label scrolls away with a long result; that is fine for a drag that starts at the header.

**Cell viewer.**

- State `viewer: CellPosition | null`.
- Open it: `onDoubleClick` on the rows container over a data cell (`closest('[data-col]')`; select that cell first if it is not the anchor); Enter in `onKeyDown` when a selection exists (opens `selection.anchor`); the menu's "View cell value" (opens `selection.anchor`).
- While `viewer` is set, `onKeyDown` returns at once (the dialog owns the keyboard).
- Render, next to the menu:

```tsx
{viewer && (
  <CellViewer
    columnName={columns[viewer.column].name}
    typeName={columns[viewer.column].typeName}
    category={columns[viewer.column].category}
    rowNumber={viewer.row + 1}
    value={getRow(viewer.row)?.[viewer.column]}
    onCopyText={onCopyText}
    onClose={() => { setViewer(null); scrollRef.current?.focus({ preventScroll: true }); }}
  />
)}
```

`rowNumber` is `viewer.row + 1` in this step; 1.3c replaces it with the row's number in the original result.

## 6. Edge cases & don'ts

- **Don't take positions from the column virtualizer's items.** Only the visible index range comes from it; `offsets` and `widths` place everything.
- **Don't keep `gridTemplateColumns`.** A grid template needs every column in the DOM.
- **Don't change the selection model or the 1.3a pure modules.** Their tests must still pass unchanged.
- **Don't `JSON.parse` and `JSON.stringify` to format a `Json` value**: numbers beyond 2^53 and trailing zeros would change. Parsing is used only to test that the text is valid JSON.
- **Don't decide "is this JSON" from the text or from `typeName`.** Only `category === 'Json'` and array/object values are formatted.
- **Don't add a dependency** (no JSON viewer, no syntax highlighter).
- **A drag that starts on a handle must not select the column** (`stopPropagation` on `pointerdown`), and a double-click on a handle must not open the viewer.
- **Resizing before any row arrived** (an empty result): `setColumnWidths` receives a full copy of the header widths with one column replaced, so the array is never partial.
- **Resizing the last column wider** grows `totalWidth`; the scroll container keeps its scroll position.
- **A very long value** (megabytes of text) is shown in full in the viewer; only the grid cell is cut at 1,000 characters.
- **The viewer opens for NULL too**, shows NULL in italics, and has "Copy value" disabled.
- **Esc in the viewer** closes only the viewer; the grid's selection stays.
- **After the viewer closes**, the focus returns to the grid so the arrow keys work again.
- **Lint has zero warnings**: no state updates in effects (the `measure()` call is not one), exhaustive deps.
- **Never commit.**
