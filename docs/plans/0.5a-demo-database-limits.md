# 0.5a Demo database and limits

## 1. Goal

A Compose setup that strangers may use: they run any SQL they like against the bundled sample database, but only to read, only there, and within limits that keep one guest from slowing down or breaking the demo for others. Plus three run limits in the app (time per run, rows per run, bytes per row) that any instance can switch on.

Roadmap step **0.5a** ([ROADMAP.md](../ROADMAP.md), "0.5 Live demo"; the row is already updated). Guest sign-in (0.5b) and hosting with HTTPS (0.5c) are not part of this.

Docs it changes: `README.md` ("Docker → With Compose", a new "Public demo setup" part, "Configuration", "Security"), `docs/api.md` (batches, cut values, `CommandFinished`, "How a script runs"), `docs/security.md` (a new "Public demo" section), the owner's local `CLAUDE.md`.

## 2. Decisions

Agreed with the owner on 2026-11-20:

- **Guests use only the bundled sample database, read-only.** Not their own databases: the server would then connect anywhere for anyone, and could be used to guess passwords on or probe other people's servers.
- **The read-only role** may read Pagila and `demo.measurements`, nothing else: no writing, no creating, no temp tables, no other database, no `rewards_report()` (it runs as the superuser), no `pg_cancel_backend`/`pg_terminate_backend` (guests share one role).
- **Only that role may log in over the network**, only to `pagila`; the superuser is refused over TCP even with its password.
- **Statement logging** for the role, so what someone tried can be looked up afterwards.
- **The database sits on an internal Docker network** with no way out to the internet.
- **Log rotation and container limits** (memory, CPU).
- **No reset:** guests can't change anything.
- **Demo values:** `CommandTimeoutSeconds` 30, `MaxRowsPerResultSet` 50,000, `MaxConcurrentQueries` 4, `MaxRunningQueriesPerUser` 1, `QueriesPerMinute` 20, `ConnectionCache:SlidingExpirationMinutes` 60; the role's `statement_timeout` 30 s, connection limit 20; `temp_file_limit` 1 GB.
- **New app limits:** a time limit per run (60 s in the demo), a total row limit per run (50,000 in the demo), and a size limit for values (1 MB in the demo). Larger values are cut.
- **`compose.demo.yaml` is an override** on top of `docker-compose.yml`, so the two setups can't drift apart; 0.5c adds Caddy to it.

Found while planning (tested against PostgreSQL 17 and Npgsql 10.0.3 on 2026-11-20), and decided here:

- **Any PostgreSQL role can change its own password and default settings** (`ALTER ROLE demo_reader PASSWORD ...`, `ALTER ROLE demo_reader SET statement_timeout = 0`), once it opens `BEGIN READ WRITE`. Privileges can't stop that. Two answers:
  - **No password check for `demo_reader` on the demo's internal network** (`trust` in the demo's `pg_hba.conf`). Changing the password then locks nobody out. Only the app is on that network, and the app lets guests reach nothing else, so this gives away nothing the guest sign-in (0.5b) won't hand out anyway.
  - **A guard in the database container** compares the role's settings with the expected ones every 10 seconds, puts them back, and logs a warning when they had been changed.
- **Large objects** (`lo_create`, `lo_creat`, `lo_from_bytea`) need no table privilege: inside `BEGIN READ WRITE` a guest could write them to disk. Their `EXECUTE` is revoked.
- **Pagila's dump gives everyone `CREATE` on schema `public`** (`GRANT ALL ON SCHEMA public TO PUBLIC`). Revoked.
- **The value limit counts per row, not per cell** (`MaxRowBytes`). A per-cell limit lets a `SELECT` of 1,000 columns of 1 MB each through. Values of 1 KB or less are never cut, so a number, a date or a boolean is always itself. Text and JSON keep their first 1,000 characters. Anything else shows only its size.
- **Results are read with `CommandBehavior.SequentialAccess`**, value by value with async reads. Without it, Npgsql loads the whole row into memory before the app can look at it, so a 500 MB value would be in memory whatever the limit says. Tested: skipping a 300 MB value kept the process at 46 MB. This holds for every instance, with or without limits.
- **A batch is also sent when its values reach about 1 MB**, for every instance. Otherwise 500 rows of 1 MB each would be one 500 MB message.
- **The run limits stop a run the way Cancel does** (through the run's cancellation token, so PostgreSQL stops the statement), but the run ends as `Failed` with the reason, which the UI already shows in the Error tab. No new status and no UI change.
- **A run stopped between two statements no longer starts the next one.** This holds for Cancel too. Before, it sent the next `StatementStarted` and then failed.
- **The new settings default to 0 (off)**, like `CommandTimeoutSeconds`. Self-hosted instances keep today's behavior apart from the two points above.
- **`demo_reader` is created in every Compose setup** (password `demo-reader` by default, `MDBNAV_DEMO_READER_PASSWORD`), so the read-only experience can be tried locally. Only `compose.demo.yaml` adds the lock-down (`pg_hba.conf`, the guard, `temp_file_limit`).

Changed while building (2026-11-20), so the files differ from sections 5 and 8 below in these points:

- **`CommandTimeoutSeconds` stays off in the demo.** Set to 30, it raced the role's 30 s `statement_timeout`; when it won, Npgsql reported only "Exception while reading from stream". Without it, a long statement ends with PostgreSQL's "canceling statement due to statement timeout", and a guest who switches that off is stopped by `MaxRunSeconds` with its own message. `compose.demo.yaml` and the security doc say so.
- **The Dockerfile creates `/usr/local/share/mdbnavigator` first** (`RUN install -d -m 755`): `COPY --chmod=644` gave the folder it created mode 644, and PostgreSQL couldn't enter it.

### `CutCellText.cs`

```csharp
using System.Globalization;

namespace MDBNavigator.Providers.PostgreSQL
{
    // What a value too large for QueryExecution:MaxRowBytes becomes. A plain string, so the cell value contract
    // (JsonCellValue, cellValue.ts) doesn't change: text keeps its beginning, anything else shows only its size.
    internal static class CutCellText
    {
        public const int PreviewChars = 1000;

        public static string For(string? preview, long totalBytes) =>
            preview is null
                ? $"[too large to show: {Size(totalBytes)}]"
                : $"{preview}… [cut: {Size(totalBytes)} in total]";

        // KB below a megabyte, rounded up so a cut value never reads "0 KB"; MB with one decimal from there.
        internal static string Size(long bytes) =>
            bytes < 1024 * 1024
                ? string.Create(CultureInfo.InvariantCulture, $"{Math.Ceiling(bytes / 1024.0):0} KB")
                : string.Create(CultureInfo.InvariantCulture, $"{bytes / (1024.0 * 1024.0):0.0} MB");
    }
}
```

The `…` is U+2026.

### `PostgresQueryRunner.cs`

New constants at the top of the class:

```csharp
        // Values of this size or less are always read whole: numbers, dates, booleans, short text. Only big values are
        // cut, so a number column never shows a note instead of a number.
        private const int SmallValueBytes = 1024;

        // A batch is sent when it has batchSize rows or its values reach this many bytes, so wide rows don't pile up
        // hundreds of megabytes in one message.
        private const int BatchTargetBytes = 1024 * 1024;
```

                // that is cut is never held in memory (Npgsql skips its bytes).
                await using var reader = await batch.ExecuteReaderAsync(CommandBehavior.SequentialAccess, ct);

3. Next to `batchRows`: `long batchBytes = 0;`. The row loop becomes:

   ```csharp

                    {
                        var (row, rowBytes) = await ReadRowAsync(reader, columns, maxRowBytes, ct);
                        batchRows.Add(row);
                        batchBytes += rowBytes;

   ```

   Everything after the loop (last batch, cancel or skip at the row limit, `NextResultAsync`, `InTransactionAfter`) stays as it is.

4. New private methods:

   ```csharp
        // One row's values, in column order (SequentialAccess allows no going back), as JSON cell values, and the
        // bytes read, for the batch's size. Async reads only: in SequentialAccess a synchronous read of a big value
        // would block a thread on the network.
        private static async Task<(object?[] Row, long Bytes)> ReadRowAsync(
            NpgsqlDataReader reader, ColumnInfo[] columns, int? maxRowBytes, CancellationToken ct)
        {
            var row = new object?[columns.Length];
            long rowBytes = 0;
            for (var i = 0; i < columns.Length; i++)
            {
                if (await reader.IsDBNullAsync(i, ct))
                {
                    continue;
                }

                // The value's size as PostgreSQL sent it, for every type. IsDBNullAsync has read it already.
                var size = reader.GetBytes(i, 0, null, 0, 0);
                if (maxRowBytes.HasValue && size > SmallValueBytes && rowBytes + size > maxRowBytes.Value)
                {
                    var cut = await CutValueAsync(reader, i, columns[i].Category, size, ct);
                    row[i] = cut;
                    rowBytes += cut.Length;
                    continue;
                }

                row[i] = JsonCellValue.From(await reader.GetFieldValueAsync<object>(i, ct));
                rowBytes += size;
            }

            return (row, rowBytes);
        }

        // Text and JSON keep their beginning, so the user still sees what the value is; anything else gets only its size.
        private static async Task<string> CutValueAsync(
            NpgsqlDataReader reader, int ordinal, DbTypeCategory category, long size, CancellationToken ct)
        {
            string? preview = null;
            if (category is DbTypeCategory.Text or DbTypeCategory.Json)
            {
                try
                {
                    using var text = await reader.GetTextReaderAsync(ordinal, ct);
                    var buffer = new char[CutCellText.PreviewChars];
                    var read = 0;
                    int count;
                    while (read < buffer.Length && (count = await text.ReadAsync(buffer.AsMemory(read), ct)) > 0)
                    {
                        read += count;
                    }

                    // Half of a surrogate pair at the end is not a character.
                    if (read > 0 && char.IsHighSurrogate(buffer[read - 1]))
                    {
                        read--;
                    }

                    preview = new string(buffer, 0, read);
                }
                catch (InvalidCastException)
                {
                    // A text type Npgsql can't read as a stream (from an extension): the size alone.
                }
            }

            return CutCellText.For(preview, size);
        }
   ```

   `columns` must be a `ColumnInfo[]` (it is: `.ToArray()`). Add `using System.Data;` for `CommandBehavior`.

These Npgsql calls were tested in this combination (Npgsql 10.0.3, PostgreSQL 17, `SequentialAccess`): `IsDBNullAsync`, then `GetBytes(i, 0, null, 0, 0)` returns the byte size for every type tried (int, text, varchar, bpchar, name, json, jsonb, xml, bytea, arrays, timestamptz, date, timetz, uuid, numeric, bigint, interval, inet, int4range, hstore, `"char"`), then `GetFieldValueAsync<object>` returns the same .NET type as `GetValue` in normal mode. `GetTextReaderAsync` works for text, varchar, bpchar, name, json, jsonb (without its version byte) and xml.

### `QueryExecution.cs`

Add `using System.Globalization;`. In `RunAsync`:

```csharp

            // database stops the statement at once. The outcome tells them apart from the user's Cancel.

```

(replacing the current `linkedCts` line; the other locals stay).

The `StreamQuery` call gets `maxRowBytes: _options.MaxRowBytes > 0 ? _options.MaxRowBytes : null,` after `maxRowsPerResultSet`.

The loop:

```csharp
                await foreach (var item in stream)
                {
                    // Once a limit has stopped the run, nothing more goes to the browser. The stream then ends with an
                    // exception at its next read or statement (PostgresQueryRunner). Never break out of the loop
                    // instead: that would dispose the reader, which reads every remaining row first.
                    if (runLimit.IsCancellationRequested)
                    {
                        continue;
                    }

                    switch (item)
                    {
                        case StatementStarted started:
                            // (as it is)
                        case QueryBatch batch:
                            await _notifier.SendBatchCommandResult(ToDto(command, batch), command.SessionId);
                            // More than the limit, not the limit itself: one result of exactly MaxRowsPerResultSet rows
                            // is complete. The batch that crosses it has been sent.
                            if (_options.MaxRowsPerRun > 0 && stats.RowCount > _options.MaxRowsPerRun)
                            {
                                rowLimitReached = true;
                                runLimit.Cancel();
                            }
                            break;
                    }
                }
```

The first `catch` becomes:

```csharp
            catch (Exception) when (linkedCts.IsCancellationRequested)
            {
                if (runLimit.IsCancellationRequested && !cancellation.IsCancellationRequested && !stoppingToken.IsCancellationRequested)
                {
                    // One of this server's limits, not the user: a failure with the reason, shown in the Error tab.
                    status = CommandExecutionStatus.Failed;
                    error = AtStatement(rowLimitReached ? RowLimitMessage() : TimeLimitMessage(), current);
                    _logger.LogInformation("Query execution {ExecutionId} stopped at the run's {Limit} limit",
                        command.ExecutionId, rowLimitReached ? "row" : "time");
                }
                else
                {
                    // Npgsql may surface a cancelled command as OperationCanceledException or PostgresException (57014).
                    status = CommandExecutionStatus.Cancelled;
                }
            }
```

A stream that ends normally is `Completed`, even if a limit fired just after its last item: nothing was left out.

### `docker/sample-db/95-demo-reader.sh`

```sh
#!/bin/sh
# demo_reader: the read-only role guests of the public demo use (docs/security.md, "Public demo"). It may read
# Pagila and demo.measurements and nothing else. Created in every setup, so a local Compose shows the same thing;
# compose.demo.yaml adds the rest (who may log in, the settings guard, temp_file_limit).
# Runs once, when the data volume is empty, after Pagila (10, 20) and the big table (90).
set -eu

: "${DEMO_READER_PASSWORD:?DEMO_READER_PASSWORD is not set}"

psql -v ON_ERROR_STOP=1 -X -q --username "$POSTGRES_USER" --dbname "$POSTGRES_DB" \
    -v reader_password="$DEMO_READER_PASSWORD" <<'SQL'
-- Enough for the app's few connections at a time; past it a guest gets "too many connections for role".
create role demo_reader login password :'reader_password' connection limit 20;

-- Only this database. CONNECT and TEMPORARY are everyone's by default.
revoke connect, temporary on database pagila from public;
grant connect on database pagila to demo_reader;
revoke connect on database postgres from public;
revoke connect on database template1 from public;

-- Pagila's dump gives everyone CREATE on public ("GRANT ALL ON SCHEMA public TO PUBLIC"). Taken back.
revoke create on schema public from public;

-- Reading only.
grant usage on schema public, demo to demo_reader;
grant select on all tables in schema public, demo to demo_reader;

-- rewards_report() runs as its owner, the superuser (SECURITY DEFINER).
revoke execute on function public.rewards_report(integer, numeric) from public;
-- Guests share this role, so these would let one cancel or end another's queries.
revoke execute on function pg_catalog.pg_cancel_backend(integer) from public;
revoke execute on function pg_catalog.pg_terminate_backend(integer, bigint) from public;
-- Large objects need no table privilege: inside BEGIN READ WRITE anyone could write them to disk.
revoke execute on function pg_catalog.lo_create(oid), pg_catalog.lo_creat(integer), pg_catalog.lo_from_bytea(oid, bytea) from public;

-- The role's settings, and what puts them back. In the postgres database, which guests can't reach.
\connect postgres

-- Any role can change its own defaults (ALTER ROLE ... SET, inside BEGIN READ WRITE). The demo's guard
-- (guard-reader.sh) calls this every 10 seconds: it does nothing while the settings are as expected, and otherwise
-- logs a warning and puts them back.
create function public.restore_demo_reader(quiet boolean default false) returns void
language plpgsql as $fn$
declare
    -- As PostgreSQL stores them (pg_db_role_setting), in "C" order.
    expected constant text[] := array[
        'default_transaction_read_only=on',
        'idle_in_transaction_session_timeout=60s',
        'log_statement=all',
        'statement_timeout=30s'];
    reader constant oid := (select oid from pg_roles where rolname = 'demo_reader');
    actual text[];
    database_name name;
begin
    select array_agg(setting order by setting collate "C") into actual
    from pg_db_role_setting, unnest(setconfig) as setting
    where setrole = reader and setdatabase = 0;

    if actual is not distinct from expected
       and not exists (select from pg_db_role_setting where setrole = reader and setdatabase <> 0) then
        return;
    end if;

    if not quiet then
        raise warning 'demo_reader''s settings had been changed (%), putting them back', actual;
    end if;

    -- Settings for one database (ALTER ROLE ... IN DATABASE) win over the role's own, so they go too.
    for database_name in
        select d.datname from pg_db_role_setting s join pg_database d on d.oid = s.setdatabase where s.setrole = reader
    loop
        execute format('alter role demo_reader in database %I reset all', database_name);
    end loop;

    alter role demo_reader reset all;
    alter role demo_reader set default_transaction_read_only = on;
    alter role demo_reader set idle_in_transaction_session_timeout = '60s';
    alter role demo_reader set log_statement = 'all';
    alter role demo_reader set statement_timeout = '30s';
end
$fn$;

revoke execute on function public.restore_demo_reader(boolean) from public;

select public.restore_demo_reader(quiet => true);
SQL
```

## Public demo

`compose.demo.yaml` turns the Compose setup into an instance strangers may use: they run any SQL they like, but only against the bundled sample database, and only to read (`docker compose -f docker-compose.yml -f compose.demo.yaml up -d --build`). Why not let guests use their own databases instead: the server would then connect anywhere for anyone, and could be used to guess passwords on, or probe, other people's servers, from the demo's address.

**The database**

- Guests connect as `demo_reader`, which may read Pagila and `demo.measurements` and nothing else: no writing, no creating (Pagila's dump gives everyone `CREATE` on `public`; that is taken back), no temporary tables, no large objects, no other database.
- `rewards_report()` runs as its owner, the superuser, so guests can't call it. Nor `pg_cancel_backend` and `pg_terminate_backend`: guests share one role and could end each other's queries.
- Only `demo_reader`, only to `pagila` and only from the app's network may log in (`docker/sample-db/demo/pg_hba.conf`). The superuser is refused over the network even with its password. - `temp_file_limit = 1GB` caps the disk one session's sorts and hashes may use; guests can't change it.

## 6. Edge cases & don'ts

- **Never break out of the `await foreach` in `QueryExecution`,** and never throw in the middle of a result in `PostgresQueryRunner`. Disposing a reader that is mid-result reads all of its remaining rows, which can take minutes. A stop goes through the token only: Npgsql then asks PostgreSQL to cancel at its next network read. The only explicit check is `ct.ThrowIfCancellationRequested()` at the top of the statement loop, where no reader is open.
- **Async reads only in `ReadRowAsync`.** `GetValue` or `GetString` in `SequentialAccess` mode can block a thread on the network for a big value. `GetBytes(i, 0, null, 0, 0)` after `IsDBNullAsync` is fine: the size is already read.
- **Values of 1 KB or less are never cut**, even when the row's budget is used up.
- **Don't change `JsonCellValue.cs` or `cellValue.ts`:** a cut value is a plain string. Don't change the UI.
- **The new settings default to 0.** The existing smoke tests (`tests/MDBNavigator.API.Tests/*Tests.cs`) must pass unchanged. Only `Infrastructure/ApiFactory.cs` and `Infrastructure/AppFixture.cs` change, as written above. Record a checksum of the existing test classes before and after, and report both.
- **Don't use `sed -i`** on repository files: on this machine it turns CRLF files into LF. Use the editor tools.
- **The Docker files must have LF line endings** (`file` reports no CRLF). A shell script with CRLF fails inside the container with a confusing "not found".
- **Init scripts run only when the data volume is empty.** Every test run starts from a new project name and ends with `down -v`.
- **Test runs must not touch the owner's things:** use the project names `mdbnav-0-5a` and `mdbnav-0-5a-local` with `MDBNAV_PORT=18080` and `18081`, and `down -v` both. Don't run `docker compose` without `-p`. Don't touch other containers, volumes or images (`PostgreSQLDB`, `what2eat-postgres`, the owner's `mdbnavigator` project). Don't connect to the owner's PostgreSQL.
- **Don't create a `.env` file;** pass test values through the command's environment.
- **Don't publish the sample database's port** in either Compose file.
- **The guard hides psql's output** (it fails quietly while PostgreSQL starts). So its real work is checked in section 8, not assumed.
- **If `samenet` doesn't let the app's connections in** (the app's connect fails with "no pg_hba.conf entry"), stop and report. Don't widen the rule to `all`.
- **If a stored setting differs from the `expected` array** (the guard then warns every 10 seconds), report what `pg_db_role_setting` holds. Don't change the expected values to whatever appears without saying so.
- **No secrets in files.** `demo-reader` is the documented local default, and the demo doesn't check that password.
